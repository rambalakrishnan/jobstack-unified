```csv
sales,soft,role family,exclude
```

**Rule:** Update boolean queries from logged vetoes. Start with hard exclusions only. Add soft exclusions later if they produce too much noise. Do not exclude “bachelor’s required” automatically—many public-sector roles waive it or accept equivalent experience, but the ATS may still reject. Flag it.

### 3.5 End-to-End 8-Step Pipeline Specification

1. **Query generator:** Slots for `[primitive verb] + [object] + [domain] + [constraint] - [hard exclusion]`.
2. **Scraper/API:** Pull full descriptions from LinkedIn, Indeed, GovernmentJobs, USAJobs, Greenhouse, Lever, county/transit sites.
3. **Normalize:** `title, org, location, salary, description, requirements`.
4. **Pre-filter:** broad boolean recall. Don’t over-exclude here.
5. **Embed:** Use `sentence-transformers` or OpenAI embeddings. Embed capability profile chunks and each job description. Cosine similarity.
6. **LLM rerank:** Score against playbooks and hard blockers.
7. **Queue:** Only jobs that pass `can_do_70`, `would_tolerate`, and `pay_ok`.
8. **Tailor:** Generate resume bullets and cover letter fragments using the JD’s vocabulary.

### 5.2 Agent Operating Rules & System Architecture (`AGENTS.md`, `docs/external/README.md`, `architectural_decomposition.txt`, `specifications_format.txt`)

#### Project Identity
Building **job-hunter**, an asynchronous multi-agent system that searches, applies, and follows up on jobs for Ram Balakrishnan.

#### The 6 Rules of Engagement (`AGENTS.md`)
1. **Read the spec first.** Every module directory contains `.omp-spec.md`. Read it before writing any code.
2. **One module at a time.** Do not modify files outside the module you are working on unless the spec explicitly allows it.
3. **No guessing business logic.** Candidate profile, address anchors, zone rules, and scoring rubrics are in `shared/candidate-profile`. Use them exactly.
4. **Never commit secrets.** API keys, service account JSONs, and PII go in the Hermes vault, never in git.

#### Greenfield Decomposition Rules (`architectural_decomposition.txt`)
1. **Domain-Driven, Not Layer-Driven:** Modules must represent business capabilities or bounded contexts. Never create top-level modules named `controllers`, `models`, `views`, `utils`, or `helpers`. Layers belong inside modules.
2. **Single Responsibility:** Each module must have exactly one reason to change. If described with "and", split it.
3. **Explicit Interfaces:** Every module exposes a public interface (functions, types, events, or REST endpoints); everything else is private.
4. **Acyclic Dependencies:** Module A may depend on B, never B on A. Break cycles via shared contract modules or events.
5. **Isolation for OMP:** Each module is executed via `omp --path ./modules/<name>` and must be self-contained (source, tests, `.omp-spec.md`, manifest).
6. **Testability:** Every module must have a deterministic `verification_command`.

**Module Record Schema:**
| Field | Description |
|-------|-------------|
| `name` | CamelCase, ≤ 32 chars (e.g., `AuthService`) |
| `path` | `./modules/<lowercase-hyphen>` (e.g., `./modules/auth`) |
| `responsibility` | One sentence, no "and" |
| `public_interface` | List of functions, types, events, endpoints |
| `dependencies` | Other module names this depends on |
| `external_dependencies` | APIs, SDKs, databases not covered by LSP |
| `verification_command` | Exact CLI command, deterministic output |

# WI session

Source: `wi/REPORT.md` §Transport + §Request Contract + Addendum, `DETAILS.md` §3 (WI), `wi/scripts/01_enum_form.py`, `02_post_search.py`, `04_postback_page.py`, `11_bot_posture.py`, `20_login_detail.py`, `21_browser_login.py`, `22_replay_details.py`, `wi/data/bot_posture.jsonl`, `wi/data/wi_storage_state.json` (cookie names only).

- **List + paging need no session.** `GET JobOrderList.aspx` works cookie-less (server sets only the F5 `BIGipServer…` persistence cookie); a paging POST from a brand-new no-cookie client using only harvested `__VIEWSTATE`/`__EVENTVALIDATION` returns page 2 with rows/pager/viewstate identical to the in-session POST — the sole byte difference is the `WebResource.axd?...&t=` render timestamp (diffed during extraction; `wi/REPORT.md` §Transport overstates this as "byte-identical"). Viewstate is machine-key MAC'd, not session-bound.
- **UA is the only header that matters** (`Chrome/131…` used throughout); `Accept`/`Accept-Language` sent but never tested as required. HTTP/1.1 negotiated; no HTTP/2 requirement. No TLS/JA3 sensitivity observed or tested.
- **No priming, no CSRF token, no referer needed** for list/paging. `JobSearch.aspx` sets `ASP.NET_SessionId` + `__cf_bm` + `_cfuvid`, but none of them are required downstream.
- **Failure marker:** out-of-range/non-advertised paging POST → HTTP 200 + 39,459 B `System Error` body. Content-check every response for `System Error` and for grid presence (`table#…GridViewJobs`).
- **Detail session (login, Phase B only):** one headed-browser login (Thorium under Xvfb, `--disable-blink-features=AutomationControlled`, creds from `~/.hermes/wi_creds`) lands on `/Default.aspx` and sets `.ADAuthCookie`; the jar (`.ADAuthCookie`, `ASP.NET_SessionId`, `BIGipServer…`, `cf_clearance`, CF/Google analytics) replays to plain httpx for detail GETs. Plain-POST and headless-Chromium logins fail the reCAPTCHA "Turing test".
- **Session lifetime UNKNOWN** (`[uncertain: site expires access "due to inactivity"; unmeasured]`). Treat any detail-fetch `302 → /Login.aspx` as *session expired*: re-run the browser login and resume, never as a data error.
- **Bot posture:** ~60 requests over ~10 min at 1.5–2 s + 8-request burst at 1.2 s → all 200, byte-identical burst bodies (82,231 B), `has_grid=true`, zero challenge markers; one 3.6 s response (jitter, not throttling). No 403/1020/"Just a moment" at any point. Cloudflare `__cf_bm` is issued but never challenges a plain httpx Chromium-UA client.
- **Robots:** `User-agent: * / Allow: /` + AI-training disallows + `Disallow: /*.axd$` — no disallow on `/Presentation/JobSeekers/*` (`wi/samples/t0_robots_*`).
- **Terms:** no anti-scraping / automated-access clause; nearest restrictive language governs employer reuse of résumés; "automat*" appears only in the Google Translate disclaimer (`wi/samples/t1_termsofuse_*`). Recorded, not editorialized: absence of a clause is not permission.
- **Request prep:** Chromium UA, timeout 30–40 s, follow redirects on list (form POST 302s to the list URL), do NOT follow redirects on detail (302 = session signal), 1.5–2 s spacing, ≤60 requests/domain discipline per sweep wave.

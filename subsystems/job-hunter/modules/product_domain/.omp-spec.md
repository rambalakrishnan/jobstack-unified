## Invariants & Test Assertions
### Invariants
- **[OWD-JOB]**: Job acquisition fields belong exclusively to crawler. Product decisions, priorities, materials, and attempt links belong exclusively to downstream. A crawler refresh preserves the separately published downstream domain; it does not copy stale downstream values back into downstream storage. Product evaluations identify the crawler revision they evaluated.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-REVISION]**: A domain revision is a complete immutable snapshot, not a patch. revision=previous_revision+1 at the owner. The first revision is 1. The key (entity, domain, revision) identifies exactly one content digest. Identical retries are idempotent; different bytes under that key are an integrity conflict. Stale expected revisions or lease epochs cannot commit.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[EK-LEASE]**: Claim atomically checks eligible resource state and absence of an unexpired lease, assigns a unique fencing lease_id and owner epoch, advances the entity revision, clears last_failure_reason, and appends evidence without changing resource_state. Completion checks lease ID, unexpired authority-clock deadline, entity/input revisions, and applicable owner/session epochs. A rejected stale completion has no effect.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-AXES]**: Exactly one authority role owns each of the five axes. Each applicable axis has exactly one bound publication writer. A writer may publish only its axis and must preserve the identity of its authoritative source. A report writer must not hold execution/application write authority. No whole-attempt status or multi-axis update command is defined here.

### 6.4 Complete publication

Every downstream write produces `W.DataDomainRevision`:

`record_type: owned_domain_revision`, `schema_version: owner-separated-write-domains/0.1.0`, `entity`, `registration_digest`, `domain: downstream`, `owner_domain`, `writer_id`, `revision`, `previous_revision`, `evidence_prefix`, `evidence_refs`, and complete `value`.

Revision is previous revision plus one. Stale expected revisions reject the entire write.

### 6.5 Private product operations

| Operation | Preconditions | Owner-local effect |
|---|---|---|
| Record evaluation | Valid matching input pins | Append immutable reference |
| Record material | Valid bytes and provenance | Append immutable reference |
| Set selection | Authorized policy or human decision | New selection with historical decision retained |
| Set track | Authorized product decision | Change only track |
| Set priority | Pinned prioritization basis | Change only priority |
| Claim work | Valid kernel lease grant | Claimed ownership |
| Renew work | Current unexpired lease | New lease reference |
| Release/reclaim work | Authorized fenced transition | Unclaimed ownership |
| Link attempt | Commission already durable | Append attempt link |

Each operation preserves unrelated downstream fields, writes no crawler fields, uses owner-local idempotency, and publishes asynchronously.

### 6.6 Selection transitions

Initial selection may become `go`, `no_go`, or `review` with evidence.

Every pairwise transition among those three states is permitted only through a new authorized decision:

- Review resolves to go or no-go.
- Go returns to review for stale inputs or new uncertainty.
- Go becomes no-go for a new veto.
- No-go returns to review for reconsideration.
- No-go becomes go only with explicit new rationale.
- Same-state revisions may add support.

Prior decisions remain journaled. Selection changes do not mutate existing commissions or stop native work. Those require separate authority and controls.

### 15.5 Product leases

Product work uses kernel leases independently of crawler leases.

The lease record retains resource, policy, issuer, authority epoch, entity/input revisions, generation, resource and eligible state, lease state, token, owner, owner/session epochs, issue/expiry points, retries, failure reason, prefix, and evidence.

Claiming does not change resource state. Completion checks current token, unexpired authority-clock deadline, revisions, and epochs. Stale completion has no effect. Failed generations increment retries at most once.

Authority restart durably fences the old epoch. Lease expiry revokes local commit authority, not evidence that native work or employer transactions stopped.

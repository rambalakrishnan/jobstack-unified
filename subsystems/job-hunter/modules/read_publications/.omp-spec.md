### Invariants
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.
- **[OWD-VIEW]**: A LogicalRow contains every declared domain slot and an exact version vector. Each nonzero slot embeds the complete domain document whose artifact digest and installation receipt it names. A zero slot means no publication in this view, or an explicitly inapplicable manual axis. Readers obtain one complete immutable row root.
- **[OWD-SEAL]**: A seal names a state and pins all domain revisions selected in a named read view. Its journaled seal-selection event pins the domain document digests and publication receipts before the resulting LogicalRow is registered. The row's input prefix includes that selection event, not its own later artifact-registration event.
- **[OWD-TIME-PROVENANCE]**: Every measurement retains clock_id, boot_id, origin, censoring, and an exact, bounded, or unavailable estimate. No cross-clock or cross-restart subtraction is permitted. Publication delay cannot be computed by subtracting arbitrary source and destination UTC annotations. Provenance and writer authorization are assigned and checked at ingestion.
- **[LIFE-PUBLICATION]**: Axis revisions are complete immutable publications. The key is (attempt_id, kind, axis, revision); a different value under the same key is an integrity conflict. Each next revision is previous_revision + 1. Only the owner-local revision check and journal commit are atomic. Publication to readers is asynchronous and cannot require another owner's transaction, acknowledgement, or payload serialization.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[EK-HASHES]**: Verify all content digests. At sequence 1, previous_event_hash is Missing(not_applicable). At sequence n>1 it equals event_hash at n-1. JournalPrefix.head_hash equals the event hash at last_sequence. Resolve an EvidenceRef by journal, sequence, event ID, hash, and JSON pointer; all must agree. A hash chain detects changed content but is not authentication.

### 5.1 LogicalRow admission

A crawler-backed evaluation consumes an immutable `W.LogicalRow` containing:

`record_type`, `schema_version`, `entity`, `registration_digest`, `registration`, `domains`, and `seal_point`.

For a job, `domains` contains exactly `crawler` and `downstream`.

Each nonzero published slot contains `revision`, `document`, `publication_ref`, and complete `snapshot`. A zero slot contains `revision: 0` and `value: Missing`.

Admission verifies:

1. Job entity and registration identity agree.
2. Registration digest matches complete bytes.
3. Crawler slot is nonzero.
4. Slot revision equals embedded revision.
5. Embedded entity, registration digest, domain, owner, and writer agree.
6. Document digest matches the complete embedded publication.
7. Publication evidence proves complete installation in the named view.
8. Seal vector matches every slot.
9. Seal-selection evidence is within its prefix.
10. Referenced bytes and evidence are available and authentic.
11. No revision identity has conflicting content.

A zero downstream slot is valid. The crawler must not initialize a pretend product revision.

#### Reference: `seam-mappings/job-hunter-seam-mapping.md#15.1`

### 15.1 Publication boundary

Owner durability and read-view visibility are separate events.

A `W.PublicationReceipt` contains:

`record_type`, `schema_version`, `receipt_id`, `entity`, `registration_digest`, `view_id`, `publisher_id`, `domain`, `revision`, `document`, `supersedes`, `observed_owner_head`, `source_prefix`, `installed_at`, `publication_ref`, and `publication_delay`.

Complete bytes are transferred, validated, and installed before pointer advance. Failure leaves the prior complete revision visible. Reordered deliveries cannot roll back the current pointer. Identical retries return the existing receipt.

Publication delay is a valid kernel measurement, not arbitrary source/destination UTC subtraction.

#### Reference: `seam-mappings/job-hunter-seam-mapping.md#15.2`

### 15.2 Seals

`W.SealPoint` contains `seal_id`, `name`, `view_id`, `versions`, `sealed_at`, `input_prefix`, and `evidence_refs`.

A seal pins locally available complete publications. It does not require global synchronous freshness or freeze future writes.

Job seals use `published`, `fetch_key_replacement`, or `evidence_updated`. Attempt seals use `commissioned`, `observation_closed`, or `evidence_updated`.

Mismatched/unknown correlation or unverified source yields no accepted execution claims. Trace mismatch may coexist with independently evidenced alternate correlation.
- **[EXT-EVIDENCE]**: ObservationItem copies an already journaled, registry-validated projection. Its metadata must match the referenced event. Nested claims, control observations, and artifact slots cite earlier supporting events, not themselves. Register/import source evidence before citing it.
- **[EXT-TIME-NULL]**: Every normalized null uses Missing with one of the six kernel reasons. Every measurement has clock_id, boot_id, origin, estimate, and censoring. Register clocks before use. Never subtract across clocks or boots; UTC is annotation only. Endpoint differences and bounds obey kernel arithmetic.
- **[EK-OBSERVATION]**: Producer IDs identify one sequence lifetime. Deduplicate identical (producer_id, producer_sequence) deliveries without duplicating effects. Conflicting content under that key is an integrity incident, not last-write-wins. Journal gaps, overflow, loss, flush receipts, and producer closure. A closed HTTP connection is not producer completeness or execution termination.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. None, protocol acknowledgement, HTTP success, and execution completion do not establish application commitment. Authentication and correlation are independent checks. A valid signature with a trace mismatch remains authenticated but not reliably correlated to the claimed attempt.
- **[LIFE-CLAIMS]**: Execution publications contain only faithfully mapped, source-attributed claims from the commissioned subject/version. Preserve raw responses, mapping versions, declared scope, original times when available, and receipt times. An absent state is Missing, not an invented subject claim of unknown. - **[LIFE-SOURCE-CHECKS]**: Verify source identity and attempt correlation independently. Preserve trace mismatch separately from authentication. An authenticated but uncorrelated message remains evidence of receipt, not an accepted claim/fact for an arbitrary attempt. Strong alternate correlation may establish the attempt despite a trace defect, but must be explicit and evidenced.

Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. ### 12.9 Observe

Request fields are `handle`, `after`, `through`, `max_items`, and `wait_limit`.

Cursor fields are `handle`, `journal_id`, `sequence`, and `event_hash`; sequence zero has inapplicable hash.

Page fields are `kind`, `handle`, `after`, `through`, `next`, `has_more`, `observation_close_ref`, `items`, and `limitations`.

Rules:

- First live page pins a cutoff.
- Continuations retain that cutoff and have zero wait.
- Entries are unique, increasing, after the incoming cursor, and within cutoff.
- Next is the last scanned journal position.
- `has_more` is exactly whether next precedes cutoff.
- Empty pages do not prove termination.
- Late evidence requires a new cutoff.
- Unavailable cursor history is explicit.
- Oversized entries are not silently skipped.

Observation items contain `event_ref`, `recorded_at`, `provenance`, `payload`, `measurements`, and `artifact_refs`. Metadata matches the cited complete journal event.

Payload kinds are `native_report`, `context_observation`, `task_output`, `connector_incident`, `control_observation`, `lifecycle_publication`, `artifact_available`, and `clock_registered`.

Lifecycle references may carry only dispatch, observation, or delegated execution.

### 11.4 Execution claims

`ExecutionValue` contains cumulative `claims`.

Each claim contains:

`claim_id`, `scope`, `state`, `application_assertions`, `native_run_id`, `native_message_id`, `native_report`, `mapping`, `source_checks`, `made_at`, `received_at`, `evidence_available_to_claimant`, `evidence_refs`, and `limitations`.

Scope is `primitive`, `application_postcondition`, `execution_lifecycle`, or `unknown`. State is an actual `running`, `completed`, `failed`, `stopped`, `unknown` claim or `Missing`.

Primitive scope has inapplicable task state and no application assertions. Unknown scope has missing state and no application assertions.

Each commitment assertion contains `assertion_id`, `value`, `span`, `boundary_ref`, and `evidence_refs`. Values are `committed`, `not_committed`, `outcome_unknown`; spans are `at_boundary`, `after_boundary`, `entire_attempt`.

Claims append, including contradictory claims. No truth-state machine suppresses later evidence. “Stopped” alone does not mean “no commitment.”

#### Reference: `seam-mappings/job-hunter-seam-mapping.md#11.6`

### 11.6 Source checks

`SourceChecks` contains `authentication`, `correlation`, `trace_correlation`, `verification_policy`, `matched_by`, and `evidence_refs`.

Authentication is `verified`, `failed`, or `unknown`. Correlation is `matched`, `mismatched`, or `unknown`. Trace correlation is `matched`, `mismatched`, `not_observed`, or `not_applicable`.

Accepted claims/facts require verified authentication, matched correlation, nonempty matching inputs, and actual verification evidence. A sender’s serialized “verified” label is insufficient.

A trace mismatch may coexist with independently established alternate correlation, but that basis must be explicit.

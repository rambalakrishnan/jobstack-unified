## Invariants & Test Assertions
### Invariants
- **[EK-MANUAL]**: Manual execution has no automation subject, connector version, or binding version. It may produce genuine production observations and origin receipts. Human actions and notes retain manual provenance and disclosed assistance. An operator note alone cannot set an authoritative business predicate.
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-ATTEMPT-SCOPE]**: An application attempt has immutable kind at commissioning. A laboratory fixture is practice and held_in. An employer origin is held_out; production requires an employer origin. derived_from references only the same kind. rehearsal_of links practice to production; performance_of links production to practice. These are lineage links, never evidence promotion.
- **[EK-REPLAY]**: Exact fixture replay consumes recorded external inputs and lifecycle observations, recomputes derived outputs, and compares semantic events, final state, and the diagnostic. It must not feed recorded derived outputs back as authoritative inputs. Diagnostic-only replay may re-derive a production diagnostic, but cannot replay an employer mutation.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-IDEMPOTENCY]**: The commissioning idempotency key is scoped to the commissioning principal and immutable attempt request. Same key and request returns the same local attempt/handle; changed content under the key is rejected. Repeated Start does not launch a second logical execution.
- **[LIFE-LINEAGE]**: kind is immutable. Laboratory fixtures are practice and held_in; employer origins are held_out and production requires an employer origin. derived_from is same-kind and acyclic. rehearsal_of points from practice to an already commissioned production identity; performance_of points from production to an already commissioned practice identity.
- **[LIFE-MANUAL]**: Manual mode requires no automation subject, native run ID, connector version, or native binding version. Its dispatch and execution slots stay at revision zero with not_applicable. The recorder owns observation and journals human actions with manual provenance.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[EXT-SURFACE]**: Recognize exactly the nine versioned verbs. The shared request surface is task-shaped and browser-agnostic. No shared Page, ElementHandle, selector engine, DOM node handle, or synchronous browser primitive is defined here. Native input formats are mapping artifacts, not a cross-browser API.
- **[EXT-READ-ONLY]**: discover_jobs and extract tasks cannot execute employer/application mutations. HTTP method alone does not determine whether an operation is read-only. The crawler cannot gain application authority through an extraction extension, plan artifact, redirect, or permissive task text.
- **[EXT-BOUNDS]**: Enforce finite local call, queue/observation, drain, cancellation-wait, and cleanup-wait bounds using registered local monotonic clocks. Admission and observation buffering are bounded; rejected work is not silently lost. An accepted queued task consumes its active observation budget.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.

## 19. End-to-end required traces

### 19.1 Crawler-backed manual production

1. Consume verified sealed crawler row.
2. Evaluate against pinned profile and policies.
3. Publish evaluation and selection downstream.
4. Generate supported materials.
5. Admit manual production manifest and commission.
6. Publish attempt link.
7. Keep dispatch/execution at revision zero and inapplicable.
8. Record human actions.
9. Capture and verify employer receipt.
10. Publish application fact.
11. Close observation.
12. Publish report with inapplicable subject comparison.
13. Display confirmed production commitment without crediting an executor.

### 19.2 Automated production with lost response

1. Admit exact subject-mode commission.
2. Prepare without execution.
3. Start with stable key.
4. Native delivery occurs but response is lost.
5. Preserve handle and dispatch uncertainty.
6. Retry only the same connector command; do not relaunch.
7. Close observation within bounds if necessary.
8. Accept later verified receipt.
9. Publish new application revision and stale-report indicator.
10. Reconcile over new pins without rewriting close-time knowledge.

### 19.3 Claimed cancellation contradicted

1. Retain an authenticated explicit entire-attempt no-commit assertion.
2. Close observation independently.
3. Receive a verified matching commitment.
4. Preserve both source histories.
5. Publish contradiction with exact claim/fact references.
6. Do not rewrite the claim to unknown or erase the commitment.

### 19.4 Practice followed by independently authorized production

1. Commission practice against the fixture.
2. Retain practice results and diagnostics.
3. Independently select a real employer target.
4. Commission production with its own permissions, profile, task, and owner bindings.
5. Optionally link `performance_of`.
6. Use only production receipt evidence for production commitment.

### 19.5 Concurrent crawler replacement and product update

1. Product owner durably commits a new downstream revision.
2. Publication may lag.
3. Crawler selects the latest fully installed downstream revision in its named view.
4. Changed fetch key archives that exact complete cut.
5. A pointer race rejects/reselects the replacement cut.
6. Product acknowledgement never waits for crawler transaction completion.
7. Archive reconstruction remains exact after subsequent publications.

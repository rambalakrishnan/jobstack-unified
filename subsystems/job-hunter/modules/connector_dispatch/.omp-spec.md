## Invariants & Test Assertions
### Invariants
- **[EXT-DESCRIBE]**: Pin a descriptor to one subject/version/configured mode/interface surface. A new subject version starts unknown on every capability until its own evidence establishes another availability. Neither presence nor absence inherits. Documentation can support a declaration, not a run-success result.
- **[EXT-DECLARE-NOT-ASSESS]**: The connector declares capabilities, mappings, observations, and source claims. It does not emit qualification, requirement satisfaction, or an authoritative application-success flag. Consumer assessment remains separate from capability availability and opportunity.
- **[EXT-TASK]**: Match the full task, scope, permissions, observation policy, assistance, and selected subject to the admitted manifest. Application work additionally matches its immutable commission, including kind and lineage. Manual commissions are not dispatchable through this contract.
- **[EXT-READ-ONLY]**: discover_jobs and extract tasks cannot execute employer/application mutations. HTTP method alone does not determine whether an operation is read-only. The crawler cannot gain application authority through an extraction extension, plan artifact, redirect, or permissive task text.
- **[EXT-PREPARE]**: Prepare is non-executing. Validate already supplied task data, plan, dependencies, mappings, grants, and declared limits without visiting the target, testing authentication, resetting context, invoking a planner, or secretly improving the plan. Record the native serialization and subject-facing task independently.
- **[EXT-PREPARATION-PIN]**: A preparation is immutable and names the exact descriptor, subject, mapping, full task, delivered task, intended native request, runtime-access references, and limitations. Start accepts that preparation digest, including all concerns requiring acceptance, under actual task authority.
- **[EXT-START]**: Before wire delivery, durably commit the local handle, immutable request binding, idempotency association, and dispatch intent under owner-local fencing. Start returns a local receipt without awaiting task completion. A native run ID is attached only in later source-backed observations.
- **[EXT-IDEMPOTENCY]**: For mutating/collecting calls, (authenticated principal, connector_id, request_id) identifies one command. Same command and identical request returns its retained receipt without another effect; conflicting content under that key is rejected. Describe and Observe are read calls whose responses may reflect newer evidence.
- **[EXT-RESUME]**: Resume requires a new command identity, the existing logical idempotency key/handle, explicit recovery authority, and an evidenced native checkpoint or idempotency contract for the same request and context. It preserves the same logical dispatch and journals each additional delivery.
- **[EXT-STATE-POLICY]**: Browser-state and framework-learning-state requests remain separate. Prepare records their mapping and limitations; actual realization is journaled after Start. An opaque context reference is not a Page or DOM handle and grants no authority by itself.
- **[EXT-BOUNDS]**: Enforce finite local call, queue/observation, drain, cancellation-wait, and cleanup-wait bounds using registered local monotonic clocks. Admission and observation buffering are bounded; rejected work is not silently lost. An accepted queued task consumes its active observation budget.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-DISPATCH]**: Prepare is non-executing. Before the first native delivery, durably allocate the connector-local handle and record the intended request digest, idempotency key, and dispatching transition. A native run ID is attached only when actually received and correlated. Local Start acknowledgement is not native acceptance; native acceptance is not execution completion.
- **[LIFE-IDEMPOTENCY]**: The commissioning idempotency key is scoped to the commissioning principal and immutable attempt request. Same key and request returns the same local attempt/handle; changed content under the key is rejected. Repeated Start does not launch a second logical execution.
- **[EK-CAPABILITY]**: A descriptor applies to exactly one subject_id, subject_version, configured mode, and interface surface. Its catalog must enumerate every capability for that scope. Every new subject version starts unknown until its own evidence establishes another availability. Omission and predecessor descriptors do not imply inheritance, presence, or absence.

### 13.1 Idempotency levels

| Level | Key and guarantee |
|---|---|
| Connector command | Principal, connector ID, request ID; identical mutating/collecting request returns retained receipt |
| Logical execution | Principal, connector ID, Start key; repeated initial Start returns same handle |
| Commission | Cannot acquire another logical execution by changing key, caller, or executor |
| Employer effect | No exactly-once guarantee without actual origin semantics |

Changed content under a reused command/key is rejected. Describe and Observe may return newer read evidence.

#### Reference: `seam-mappings/job-hunter-seam-mapping.md#13.2`

### 13.2 Failure recovery

| Failure | Required action |
|---|---|
| Prepare response lost | Retry identical command; no hidden replanning |
| Stale preparation | Reject; no silent reprepare |
| Start response lost | Retry same command/key |
| Delivery may have occurred | Preserve uncertainty; observe and reconcile |
| Native acceptance known, terminal response lost | Continue observation; do not relaunch |
| Late callback | Authenticate, correlate, append |
| Transport closed | Do not infer cancellation |
| Lease expired | Fence local commit only; do not infer noncommitment |
| Executor unavailable after uncertain delivery | No automatic executor switch |
| Artifact lost | Preserve known identity and record loss |
| Journal repair needed | Never repeat employer mutation to repair local evidence |

Resume requires existing handle/key, same request/context, checkpoint artifact, native resume contract, authorization, evidence, and an open observation window. `ResumeAuthorization` contains `handle`, `checkpoint`, `native_resume_contract`, `authorization_refs`, and `evidence_refs`.

Resume uses a new command identity but the same logical execution. It never repeats completed side-effecting steps.

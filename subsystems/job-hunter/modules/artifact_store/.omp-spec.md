### Invariants
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[EK-HASHES]**: Verify all content digests. At sequence 1, previous_event_hash is Missing(not_applicable). At sequence n>1 it equals event_hash at n-1. JournalPrefix.head_hash equals the event hash at last_sequence. Resolve an EvidenceRef by journal, sequence, event ID, hash, and JSON pointer; all must agree. A hash chain detects changed content but is not authentication.
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[OWD-RETENTION]**: A live replacement pins its archive root and every transitive immutable dependency. A retained later archive containing that replacement's backward link also keeps the earlier archive alive. Publishing a newer job revision, deleting a cache entry, or passing a TTL cannot release those dependencies.
- **[EXT-ARTIFACTS]**: Install immutable artifact bytes durably before journal references. Artifact names and digests resolve only within the authorized handle's retained evidence or declared native retrieval mapping. Do not fetch arbitrary caller URLs or filesystem paths through CollectArtifacts.

### 15.4 Archive and retention

`W.ArchiveRecord` contains `record_type`, `schema_version`, `root`, `storage_manifest`, and complete `payload_json`.

The root hashes the canonical storage manifest, not the expanded wrapper. The manifest contains `encoding`, `schema_version`, `entity`, `registration`, `domains`, and `seal_point`.

Expansion reconstructs the exact complete old logical row without consulting mutable peer state. Hash lists or crawler-only snapshots are insufficient.

`FetchKeyReplacement` retains `replacement_id`, entity and registration identity, old crawler pin/key, complete new crawler revision, archive root, archived vector, retention pin ID, commit reference, prefix, and evidence references.

`RetentionPinRevision` retains pin/owner/writer identity, revision pair, dependent, archive root, state, release reference, prefix, and support. State is active or released. Release requires evidenced retirement; transitive roots remain protected.

Loss is an integrity incident, not successful garbage collection.

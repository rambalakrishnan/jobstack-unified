## Invariants & Test Assertions
### Invariants
- **[OWD-VIEW]**: A LogicalRow contains every declared domain slot and an exact version vector. Each nonzero slot embeds the complete domain document whose artifact digest and installation receipt it names. A zero slot means no publication in this view, or an explicitly inapplicable manual axis. Readers obtain one complete immutable row root.
- **[OWD-ATTEMPT]**: Attempt slots contain the exact lifecycle AxisRevision publications. Their outer slot revision equals the embedded axis revision; the axis, attempt identity, commission digest, owner_domain, and writer_id match registration and commission. The reconciler writes only report.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.
- **[LIFE-AXES]**: Exactly one authority role owns each of the five axes. Each applicable axis has exactly one bound publication writer. A writer may publish only its axis and must preserve the identity of its authoritative source. A report writer must not hold execution/application write authority. No whole-attempt status or multi-axis update command is defined here.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[LIFE-REPORT-COVERAGE]**: Every claim and application assertion in the pinned execution publication is accounted for by a comparison or an explicit scope/uncertainty limitation. Any proved contradiction makes report.state contradicted, even if other comparisons remain incomplete. With no contradiction, complete comparisons yield reconciled; unresolved comparisons yield Missing with reason. No applicable subject claims yield not_applicable coverage, not a fabricated successful comparison.
- **[EK-NULL]**: Every null is Missing(value=null, reason=<one of the six reasons>). Empty arrays mean an established empty collection, not unknown contents. Unknown semantic states remain explicit enums; false and zero are never missing-value sentinels. manual_override requires an authenticated journaled operator decision and preserves the superseded observation.

### 17.5 Dashboard

The dashboard consumes an HTTP API independent of orchestrator language.

It must display:

- Product selection and its basis.
- Crawler input revision and coverage.
- Evaluation/profile/policy freshness.
- Attempt kind and target.
- All five axes or explicit inapplicability.
- Close-time knowledge separately from later facts.
- Report coverage and input-pin staleness.
- Missing/lost evidence.
- Duplicate-risk and integrity issues.

It must not offer a generic “set application status” write. Buttons submit authorized commands such as selecting a job, commissioning, requesting a control, or recording a manual observation.

#### Reference: `seam-mappings/job-hunter-seam-mapping.md#11.8`

### 11.8 Snapshot

`AttemptSnapshot` contains `record_type`, `schema_version`, `attempt`, `commission`, `commission_digest`, `input_prefix`, all five axis slots, and `seal_point`.

Seal names are `commissioned`, `observation_closed`, and `evidence_updated`. Vectors match slots exactly. A closed seal requires closed observation.

Snapshots are read compositions, never whole-attempt update commands. A current snapshot may contain newer facts than its report; the dashboard must display that staleness.

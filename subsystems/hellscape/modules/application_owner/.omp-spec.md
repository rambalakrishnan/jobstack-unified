## Invariants & Test Assertions
### Invariants
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[LIFE-ORIGIN]**: An application fact must identify the commissioned origin, candidate, job, and attempt, and cite verified source and correlation evidence under the pinned origin policy. A local fixture fact cites its transaction; a production fact cites an actual verified origin receipt. HTTP 200, a submit click, a subject result, or an operator assertion alone is insufficient.
- **[LIFE-CONTROLS]**: RequestNativeCancel, CloseObservationConnection, ReleaseNativeContext, and Contain are separately evidenced operations. A request is not an acknowledgement; acknowledgement is not an observed effect. A stop claim is retained as a subject claim, not upgraded to a no-commit fact.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-SESSION]**: Hellscape application state is reducer-owned; observation cannot set accepted data, identity verification, or commitment. The diagnostic domain cites exact application and observation input revisions and a journal prefix. It cannot amend either source to fit a finding.
- **[OWD-ATTEMPT]**: Attempt slots contain the exact lifecycle AxisRevision publications. Their outer slot revision equals the embedded axis revision; the axis, attempt identity, commission digest, owner_domain, and writer_id match registration and commission. The reconciler writes only report.

### 4.7 Transaction boundaries

**Application transaction:** atomically commits admitted command, idempotency record, reducer effect, business events, replayable response, resulting state revision, and local outbox metadata.

**Observation transaction:** atomically commits authenticated ingress, producer deduplication, installed-artifact registrations, authorized observations, gap/conflict/loss evidence, observation materialization, and local outbox metadata.

**Diagnostic transaction:** atomically registers already installed diagnostic/report bytes, advances the diagnostic-owned revision, records exact input pins, and publishes local metadata.

No transaction spans these boundaries.

### 6.6 SessionApplicationValue

| Field | Mapping |
|---|---|
| `state_revision` | Reducer revision, distinct from publication revision |
| `workflow_state` | Eight-state enum |
| `selected_job` | Accepted identifier or Missing |
| `accepted_sections` | Current contact/history/review acceptance |
| `upload` | Accepted artifact or Missing |
| `identity_receipt` | Verified receipt artifact or Missing |
| `authoritative_state` | Full immutable reducer and idempotency snapshot |
| `submission` | Fixture commitment or Missing |
| `mutation_authority` | `open` or `sealed` |
| `authority_seal_ref` | Actual seal evidence, otherwise inapplicable |

Each section acceptance contains section, value revision, validation generation, accepted-data artifact, and support.

Each fixture commitment contains application ID, operation key, request digest, receipt artifact, committed-at time, and commit reference.

The authoritative-state artifact retains selected job, all current section revisions/generations/accepted values, upload metadata/digest, identity epoch and verification, review dependencies, submission, authority state, and complete operation-response ledger.

Publication metadata and the artifact’s own digest are excluded from that artifact.

### 6.7 Confirmation rendering

Legacy `confirmation_rendered` leaves application state.

The replacement is a fixture-client or manual observation with source provenance, retained in `SessionObservationValue.confirmation_render_refs`.

Commitment, receipt retrieval, and receipt rendering are three separate facts.

Missing rendering telemetry cannot erase commitment.

### 9.6 Application history

Each origin fact contains:

- Fact/origin/candidate/job IDs.
- Committed or not-committed state.
- At-boundary or final-for-attempt coverage.
- Boundary reference.
- Origin application ID/revision.
- Receipt artifact.
- Verification kind.
- Verified checks.
- Authority-seal reference.
- Occurrence/receipt times.
- Support.

Hellscape uses local-origin-transaction verification.

Final absence requires origin-owned finality, not observation timeout. Sealing must fence new mutations and account for already admitted transactions.

An earlier as-of absence and later commitment are compatible.

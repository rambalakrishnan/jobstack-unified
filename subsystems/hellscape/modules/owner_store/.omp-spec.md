## Invariants & Test Assertions
### Invariants
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-JOURNAL]**: An acknowledged event is durably appended. Sequences are contiguous and strictly increasing within a journal, beginning at 1. The first event is manifest_admitted and pins the complete immutable manifest. All subsequent events name the same run, journal, and manifest digest. Events are never edited, deleted, resequenced, or backdated into an earlier prefix.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[EK-LEASE]**: Claim atomically checks eligible resource state and absence of an unexpired lease, assigns a unique fencing lease_id and owner epoch, advances the entity revision, clears last_failure_reason, and appends evidence without changing resource_state. Completion checks lease ID, unexpired authority-clock deadline, entity/input revisions, and applicable owner/session epochs. A rejected stale completion has no effect.
- **[EK-LEASE-RESTART]**: leased_at and lease_expires_at use one registered lease-authority clock and boot; expiry must be later than issue. Renewal requires a still-current token and epoch. On authority restart, durably fence the old authority epoch before reclaiming its leases. Never compare old offsets with the new boot, and never infer elapsed downtime from UTC.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-REVISION]**: A domain revision is a complete immutable snapshot, not a patch. revision=previous_revision+1 at the owner. The first revision is 1. The key (entity, domain, revision) identifies exactly one content digest. Identical retries are idempotent; different bytes under that key are an integrity conflict. Stale expected revisions or lease epochs cannot commit.
- **[OWD-RETENTION]**: A live replacement pins its archive root and every transitive immutable dependency. A retained later archive containing that replacement's backward link also keeps the earlier archive alive. Publishing a newer job revision, deleting a cache entry, or passing a TTL cannot release those dependencies.

### 4.1 Database allocation

| Database | Local authority | Authoritative session value |
|---|---|---|
| `application.db` | Application origin | `OWD.SessionApplicationValue` |
| `observation.db` | Observation recorder/ingester | `OWD.SessionObservationValue` |
| `diagnostic.db` | Analyzer and separately authorized admission/composition services | `OWD.SessionDiagnosticValue` and immutable control/composition metadata |

All three use SQLite WAL and `synchronous=FULL`.

Each has independent:

- Connections.
- Writer queue.
- Transaction admission.
- Checkpoint scheduling.
- Journal sequencing.
- Failure reporting.
- Artifact installation work.
- Publication outbox.

Prohibited mechanisms:

- `ATTACH DATABASE` for shared commits.
- Cross-database transactions.
- A single serialized writer for all three databases.
- Application acknowledgement waiting for observation or diagnostic publication.
- Diagnostic work holding an application write lock.

A shared disk is still a shared resource. Database separation alone is not proof of I/O isolation.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#4.7`

### 4.7 Transaction boundaries

**Application transaction:** atomically commits admitted command, idempotency record, reducer effect, business events, replayable response, resulting state revision, and local outbox metadata.

**Observation transaction:** atomically commits authenticated ingress, producer deduplication, installed-artifact registrations, authorized observations, gap/conflict/loss evidence, observation materialization, and local outbox metadata.

**Diagnostic transaction:** atomically registers already installed diagnostic/report bytes, advances the diagnostic-owned revision, records exact input pins, and publishes local metadata.

No transaction spans these boundaries.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#4.8`

### 4.8 Artifact installation

Before a database references new bytes:

1. Write a bounded temporary file.
2. Hash exact bytes.
3. Flush file data.
4. Atomically install under the owner’s content-addressed root.
5. Perform required filesystem durability operations.
6. Commit the database reference.

A crash may leave an unreferenced artifact. It must not leave an acknowledged upload pointing to absent bytes.

Byte identity and session association are separate records; one artifact may be retained by multiple sessions.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#11.6`

### 11.6 Retention

Retained manifests, prefixes, diagnostics, replay bundles, rows, and archives protect all transitive dependencies.

GC requires journaled proof that no retained root reaches the object and fencing against concurrent pin creation.

TTL expiry or a newer publication alone does not release dependencies.

Artifact loss records observation loss and preserves known identity. It is not successful GC.

Credentials remain outside ordinary evidence payloads. Restricted native bodies and sensitive receipts remain access-controlled. Redaction creates a new artifact and cannot silently preserve an exact-replay claim requiring removed bytes.

## Invariants & Test Assertions
### Invariants
- **[EK-ATTEMPT-SCOPE]**: An application attempt has immutable kind at commissioning. A laboratory fixture is practice and held_in. An employer origin is held_out; production requires an employer origin. derived_from references only the same kind. rehearsal_of links practice to production; performance_of links production to practice. These are lineage links, never evidence promotion.
- **[EK-ASSESSMENT]**: Capability, opportunity, and result are independent fields. satisfied or violated requires a valid exposed opportunity, applicable controls, and supporting evidence. native_absence requires a required, evidenced absent native capability in the exact scope, not mere failure to reach a step. Unexposed work is not_exercised; blocked or invalidly controlled work is not_exercised or indeterminate according to what was actually observed.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-LINEAGE]**: kind is immutable. Laboratory fixtures are practice and held_in; employer origins are held_out and production requires an employer origin. derived_from is same-kind and acyclic. rehearsal_of points from practice to an already commissioned production identity; performance_of points from production to an already commissioned practice identity.
- **[EXT-TASK]**: Match the full task, scope, permissions, observation policy, assistance, and selected subject to the admitted manifest. Application work additionally matches its immutable commission, including kind and lineage. Manual commissions are not dispatchable through this contract.
- **[OWD-SESSION]**: Hellscape application state is reducer-owned; observation cannot set accepted data, identity verification, or commitment. The diagnostic domain cites exact application and observation input revisions and a journal prefix. It cannot amend either source to fit a finding.

### 12.1 M1 cooperative profile

M1 admits zero hostile features:

- Visible ordinary labels and native controls.
- Stable layout and semantic identities.
- Light DOM controls.
- No frame/root challenge.
- No class churn, decoys, delayed hydration, or idle trap.
- No injected transport failure.
- No production challenge service.
- No artificial timing race.
- Normal validation, upload, identity, state transition, and submission guards.

Readiness occurs after relevant controls render and enable. Network silence is not readiness.

Autosave is not required. Later autosave/WebSocket behavior cannot displace reducer authority.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#12.2`

### 12.2 Feature-pack contract

Each later feature pack must pin:

- Typed parameter domains.
- Dependencies and exclusions.
- Registered primitive recipes.
- Human-completion or degradation contract.
- Exposure/activation event kinds.
- Expected failure signatures.
- Regression cases.
- Asset and schema digests.

Manifests contain parameters and registered recipes, not executable JavaScript.

No runtime eval, downloaded executable feature code, or native plugin loading is admitted.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#12.5`

### 12.5 Compiler rejection rules

Completion tasks are rejected if they:

1. Hide required controls without a human path.
2. Require an observational mock to satisfy verification.
3. Permanently reject every required verifier.
4. Exceed budget by construction.
5. Remove all recovery while requiring recovery.
6. Require unavailable fixture browser capability.

Permanent rejection may be valid for explicitly commissioned graceful degradation.

Undeclared fixture failure invalidates the affected opportunity. It is a fixture bug, not extra hostility.

Fast-campaign artificial delays are generally bounded to at most 5000 ms. Longer waits require a separately declared soak profile.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#12.6`

### 12.6 Curriculum and recommendations

Curriculum consumes versioned finalized evidence and journaled operator decisions.

It creates new manifests only.

Per-subject lineages remain parallel and non-alternating. Subject version, assistance, context policy, and feature exposure remain attribution boundaries.

Inner variant proposals and outer reviewed fix proposals are separate features. A proposed fix requires reviewed rule-class authority and supporting evidence. No automatic subject patching is introduced.

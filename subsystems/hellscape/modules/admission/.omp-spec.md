## Invariants & Test Assertions
### Invariants
- **[EK-ATTEMPT-SCOPE]**: An application attempt has immutable kind at commissioning. A laboratory fixture is practice and held_in. An employer origin is held_out; production requires an employer origin. derived_from references only the same kind. rehearsal_of links practice to production; performance_of links production to practice. These are lineage links, never evidence promotion.
- **[EK-MANUAL]**: Manual execution has no automation subject, connector version, or binding version. It may produce genuine production observations and origin receipts. Human actions and notes retain manual provenance and disclosed assistance. An operator note alone cannot set an authoritative business predicate.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-LINEAGE]**: kind is immutable. Laboratory fixtures are practice and held_in; employer origins are held_out and production requires an employer origin. derived_from is same-kind and acyclic. rehearsal_of points from practice to an already commissioned production identity; performance_of points from production to an already commissioned practice identity.
- **[LIFE-MANUAL]**: Manual mode requires no automation subject, native run ID, connector version, or native binding version. Its dispatch and execution slots stay at revision zero with not_applicable. The recorder owns observation and journals human actions with manual provenance.
- **[LIFE-IDEMPOTENCY]**: The commissioning idempotency key is scoped to the commissioning principal and immutable attempt request. Same key and request returns the same local attempt/handle; changed content under the key is rejected. Repeated Start does not launch a second logical execution.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.

### 5.1 Admission is a saga

Admission proceeds through independently durable steps:

1. Authenticate and authorize the commissioner.
2. Validate complete configuration and finite limits.
3. Enforce practice/held-in partitioning.
4. Install primary manifest and required artifacts.
5. Commit primary manifest admission.
6. Register the attempt commission.
7. Register attempt and session owner bindings.
8. Asynchronously initialize application and observation owners.
9. Record their initialization receipts.
10. Make the entry usable and permit subject preparation only after required initialization.

A durably admitted session receives a diagnostic even if subsequent initialization fails, subject to explicit storage-failure limitations.

A failure before durable admission is an admission refusal, not a lost admitted session.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#5.3`

### 5.3 AttemptContext and lineage

`AttemptContext` retains attempt ID, kind, target class/ID, evaluation partition, rehearsal links, performance links, and derivation links.

For Hellscape:

- Performance links are empty.
- Rehearsal links may point to already commissioned production attempts.
- Derivation links point only to practice attempts.
- Links resolve, match kind, and form no derivation cycle.
- No reciprocal mutation of an earlier commission is required.
- Links convey lineage, not inherited commitment or qualification.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#5.4`

#### Reference: `seam-mappings/hellscape-seam-mapping.md#5.5`

### 5.5 Execution and assistance fields

`ExecutionDescriptor` contains mode, subject, connector version, binding version, and assistance.

Manual mode requires subject, connector version, and binding version to be `Missing(not_applicable)`.

`AssistanceRecord` contains:

- Planning owner.
- Assistance track.
- Planner identity.
- Plan artifact or Missing.
- Online-replanning permission.
- Description.

Preparation costs and public observation inputs remain separately journaled evidence.

`SubjectIdentity` contains subject ID/version, revision basis, native revision, configured mode, interface surface, configuration digest, and stack.

Each stack component contains component name, reported version, build digest, and configuration digest.

An operator-attested version key does not invent a native revision endpoint.

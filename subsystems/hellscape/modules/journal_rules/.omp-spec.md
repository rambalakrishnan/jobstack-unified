## Invariants & Test Assertions
### Invariants
- **[EK-JOURNAL]**: An acknowledged event is durably appended. Sequences are contiguous and strictly increasing within a journal, beginning at 1. The first event is manifest_admitted and pins the complete immutable manifest. All subsequent events name the same run, journal, and manifest digest. Events are never edited, deleted, resequenced, or backdated into an earlier prefix.
- **[EK-HASHES]**: Verify all content digests. At sequence 1, previous_event_hash is Missing(not_applicable). At sequence n>1 it equals event_hash at n-1. JournalPrefix.head_hash equals the event hash at last_sequence. Resolve an EvidenceRef by journal, sequence, event ID, hash, and JSON pointer; all must agree. A hash chain detects changed content but is not authentication.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[EK-TIME]**: Every Measurement and TimePoint identifies its origin, clock, and boot. Register clocks in the manifest or a clock_registered event. Persist monotonic offsets relative to that boot. A clock_registered event may atomically introduce the clock used for its own receipt timestamp. Never subtract across clock IDs or boots. UTC is annotation only.
- **[EK-DIAGNOSTIC]**: A diagnostic is a deterministic function of its immutable manifest, named journal prefix, and pinned classifier bundle. The bundle includes requirement and optional fix registries. It uses no current wall time, unrecorded network lookups, or mutable application rows as additional evidence.
- **[LIFE-EVIDENCE]**: The journal is the source of truth. Every publication cites its supporting prefix and source evidence; it is itself registered after its bytes exist. Do not put the publication's own registration event or digest inside its derivation inputs. Imported evidence must be registered locally with its original scope and trust, not promoted by the act of import.

### 3.3 Evidence references

`EvidenceRef` contains exactly:

- `journal_id`
- `sequence`
- `event_id`
- `event_hash`
- `pointer`

The pointer is a valid JSON Pointer; empty string cites the complete event.

All coordinates must agree. A legacy event ID alone must be resolved to a complete retained reference. Unresolvable legacy references remain historical data with explicit limitations, not fabricated EK references.

`JournalPrefix` contains:

- `journal_id`
- `last_sequence`
- `head_hash`

A diagnostic can cite only evidence available through its named prefix, including locally registered imports and their retained dependencies.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#4.5`

### 4.5 Owner-local journals and primary composition journal

Each database has its own ordering authority and journal.

Each journal:

- Starts at sequence 1.
- Begins with `manifest_admitted`.
- Pins its complete immutable manifest.
- Uses contiguous sequences and an EK hash chain.

The primary session composition journal resides in `diagnostic.db`. Its manifest is referenced by the session identity, commission, diagnostic, and replay receipt.

Application and observation manifests have their own journal IDs and owner domains. They preserve the admitted attempt, task, execution configuration, and effective fixture configuration, but are distinct complete manifests with distinct digests.

Source sequences are never copied into the primary journal as if they were locally assigned sequences.

### 7.2 Complete JournalEnvelope

Every stored envelope contains:

- Record type/version.
- Run ID.
- Journal ID.
- Manifest hash.
- Journal sequence.
- Event ID.
- Event kind/version.
- Role.
- Assertion kind.
- Owner domain.
- Producer ID/sequence.
- Provenance.
- Evidence scope.
- Recorded time.
- Occurrence time.
- Causal references.
- Payload.
- Previous-event hash.
- Event hash.

Payload contains exactly data, measurements, evidence references, and artifact references.

Every nested artifact is listed for retention. Observed metrics belong in typed measurements, not untyped timing fields.

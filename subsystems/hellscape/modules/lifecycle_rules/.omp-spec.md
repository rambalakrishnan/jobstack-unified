## Invariants & Test Assertions
### Invariants
- **[LIFE-AXES]**: Exactly one authority role owns each of the five axes. Each applicable axis has exactly one bound publication writer. A writer may publish only its axis and must preserve the identity of its authoritative source. A report writer must not hold execution/application write authority. No whole-attempt status or multi-axis update command is defined here.
- **[LIFE-PUBLICATION]**: Axis revisions are complete immutable publications. The key is (attempt_id, kind, axis, revision); a different value under the same key is an integrity conflict. Each next revision is previous_revision + 1. Only the owner-local revision check and journal commit are atomic. Publication to readers is asynchronous and cannot require another owner's transaction, acknowledgement, or payload serialization.
- **[LIFE-DISPATCH]**: Prepare is non-executing. Before the first native delivery, durably allocate the connector-local handle and record the intended request digest, idempotency key, and dispatching transition. A native run ID is attached only when actually received and correlated. Local Start acknowledgement is not native acceptance; native acceptance is not execution completion.
- **[LIFE-CLOSE]**: Active observation, transport connection, native execution, application mutation authority, and native context lifetime are distinct. On the local active deadline or end request, stop issuing workflow commands, record native-cancel availability and any attempt, record transport closure, and drain effects/evidence only within the commissioned bound.
- **[LIFE-CLAIMS]**: Execution publications contain only faithfully mapped, source-attributed claims from the commissioned subject/version. Preserve raw responses, mapping versions, declared scope, original times when available, and receipt times. An absent state is Missing, not an invented subject claim of unknown. Explicit unknown remains a valid subject claim.
- **[LIFE-ORIGIN]**: An application fact must identify the commissioned origin, candidate, job, and attempt, and cite verified source and correlation evidence under the pinned origin policy. A local fixture fact cites its transaction; a production fact cites an actual verified origin receipt. HTTP 200, a submit click, a subject result, or an operator assertion alone is insufficient.
- **[LIFE-RECONCILE]**: The reconciler reads pinned execution claims and origin facts and writes only report. Compare propositions at their actual scope and knowledge boundary. A stopped claim alone does not assert that an already dispatched origin transaction cannot commit.
- **[LIFE-REPORT-COVERAGE]**: Every claim and application assertion in the pinned execution publication is accounted for by a comparison or an explicit scope/uncertainty limitation. Any proved contradiction makes report.state contradicted, even if other comparisons remain incomplete. With no contradiction, complete comparisons yield reconciled; unresolved comparisons yield Missing with reason. No applicable subject claims yield not_applicable coverage, not a fabricated successful comparison.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[LIFE-MANUAL]**: Manual mode requires no automation subject, native run ID, connector version, or native binding version. Its dispatch and execution slots stay at revision zero with not_applicable. The recorder owns observation and journals human actions with manual provenance.
- **[LIFE-TIME]**: All measured durations use Measurement with clock_id, boot_id, origin, discriminated estimate, and censoring. Endpoint subtraction requires one registered clock/boot/origin and ordered endpoints; exact zero is valid. UTC annotations and receipt order cannot establish cross-clock occurrence order. Opaque origin revisions are not lexically ordered as timestamps.
- **[EK-CLAIMS]**: Preserve claim source, semantic scope, receipt time, and knowledge boundary. None, protocol acknowledgement, HTTP success, and execution completion do not establish application commitment. Authentication and correlation are independent checks. A valid signature with a trace mismatch remains authenticated but not reliably correlated to the claimed attempt.

### 9.1 AxisRevision

Every axis revision contains record/version, attempt, commission digest, axis, owner domain, writer, revision, previous revision, evidence prefix, support, and complete typed value.

Exactly one authorized writer publishes each applicable axis. A report writer has no execution/application grant.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#9.2`

### 9.2 Dispatch transitions

| From | Allowed next |
|---|---|
| Unpublished | Not started, prepared, rejected |
| Not started | Prepared, rejected |
| Prepared | Dispatching, rejected |
| Dispatching | Accepted, rejected, uncertain |
| Uncertain | Uncertain, accepted, rejected |
| Accepted | Accepted |
| Rejected | Rejected |

`DispatchValue` contains state, local handle, native ID, request digest, delivery references, acceptance references, recovery-authorization references, and reason.

Guards:

- Prepared requires request digest.
- Dispatching requires durable handle/request/intent.
- Accepted requires correlated native evidence.
- Rejection after possible delivery requires non-acceptance evidence.
- Lost acknowledgement yields uncertain.
- Same-state revisions add evidence, not another execution.

Legacy mapping:

| Legacy | Shared |
|---|---|
| `prepared` | Prepared |
| `dispatch_beginning` | Dispatching; uncertain after ambiguous crash |
| `in_flight` | Dispatching or accepted according to evidence |
| `dispatch_uncertain` | Uncertain |
| `terminal_received` | Accepted plus separate execution claim |
| `transport_closed` | Observation control, dispatch unchanged |
| `timed_out` | Observation deadline, not native failure |
| `contained` | Containment evidence, not execution outcome |

### 9.3 Observation transitions

| From | Allowed next |
|---|---|
| Unpublished | Not opened, open, closed |
| Not opened | Open, closed |
| Open | Open, draining, closed |
| Draining | Draining, closed |
| Closed | Closed |

`ObservationValue` contains state, window ID, opened time, active deadline, drain start/deadline, closed time, close reason, close snapshot, cumulative controls, late evidence, and measurements.

Reasons are normal completion, operator stop, local deadline, translation failure, launch failure, subject terminal, connection lost, or infrastructure interruption.

Closed-first publication is valid for launch/translation failure.

Closed-to-closed preserves original closure fields while appending late/cleanup evidence.

### 9.5 Execution history

Execution publications contain cumulative immutable claims, not a latest-state overwrite.

Each claim contains:

- Claim ID/scope.
- Claimed state or Missing.
- Application assertions.
- Native run/message IDs.
- Raw report artifact.
- Mapping pin.
- Verified checks.
- Made/received times.
- Claimant-available evidence.
- Support and limitations.

States are running, completed, failed, stopped, or explicit unknown.

Missing state is not an explicit unknown claim.

Primitive claims have inapplicable execution state and no application assertions.

Each commitment assertion has ID, value, temporal span, boundary reference, and support. Values are committed, not committed, or outcome unknown; spans are at boundary, after boundary, or entire attempt.

Contradictory claims remain preserved.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#9.6`

### 9.6 Application history

Each origin fact contains:

- Fact/origin/candidate/job IDs.
- Committed or not-committed state.
- At-boundary or final-for-attempt coverage.
- Boundary reference.
- Origin application ID/revision.
- Receipt artifact.
- Verification kind.
- Verified checks.
- Authority-seal reference.
- Occurrence/receipt times.
- Support.

Hellscape uses local-origin-transaction verification.

Final absence requires origin-owned finality, not observation timeout. Sealing must fence new mutations and account for already admitted transactions.

An earlier as-of absence and later commitment are compatible.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#9.7`

### 9.7 Report history

`ReportValue` contains state, coverage, input pins, evaluator, comparisons, issues, limitations, and optional already-journaled diagnostic.

Decided state is reconciled or contradicted. Undecidable/inapplicable state uses Missing.

Coverage is complete, incomplete, or inapplicable.

Each comparison contains claim/assertion IDs, claim reference, fact IDs/references, result, temporal relation, rationale, and limitations.

Results are consistent, contradicted, not comparable, or indeterminate.

Temporal relation requires same-clock evidence, causality, or documented origin sequence. Receipt order is insufficient.

Issues include origin conflict, subject conflict, insufficient evidence, incomparable scope, untrusted observation, mapping error, and multiple commitments.

Any proved contradiction yields contradicted. Otherwise unresolved comparisons remain incomplete/Missing. No subject claims yield inapplicable coverage, not an invented successful comparison.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#16.5`

### 16.5 Lifecycle and diagnostic corpus

Required cases include:

- Local accepted Start without native acceptance.
- Delivery uncertainty after crash.
- Native completion without application commitment.
- Application commitment without confirmation rendering.
- Close-time unknown followed by commitment.
- Entire-attempt no-commit contradicted by commitment.
- Stopped claim without no-commit assertion.
- Invalid isolation write control.
- Missing dependency classified as prerequisite/environment.
- Adapter overclaim classified at connector/harness locus.
- Unexposed feature receives no pass/fail credit.
- Fixture defect invalidates only affected opportunity.
- Contradictory native messages remain cumulative.
- Manual dispatch/execution remain unpublished/inapplicable.
- Report input pins become visibly stale after new facts.
- Late evidence creates a new diagnostic revision.
- Old diagnostic bytes remain unchanged.
- Replay mismatch and unavailable remain distinct.
- Replay invokes no external effect.

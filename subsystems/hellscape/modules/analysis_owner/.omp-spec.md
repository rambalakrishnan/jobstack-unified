## Invariants & Test Assertions
### Invariants
- **[EK-DIAGNOSTIC]**: A diagnostic is a deterministic function of its immutable manifest, named journal prefix, and pinned classifier bundle. The bundle includes requirement and optional fix registries. It uses no current wall time, unrecorded network lookups, or mutable application rows as additional evidence.
- **[EK-JOURNAL]**: An acknowledged event is durably appended. Sequences are contiguous and strictly increasing within a journal, beginning at 1. The first event is manifest_admitted and pins the complete immutable manifest. All subsequent events name the same run, journal, and manifest digest. Events are never edited, deleted, resequenced, or backdated into an earlier prefix.
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[LIFE-RECONCILE]**: The reconciler reads pinned execution claims and origin facts and writes only report. Compare propositions at their actual scope and knowledge boundary. A stopped claim alone does not assert that an already dispatched origin transaction cannot commit.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[OWD-SESSION]**: Hellscape application state is reducer-owned; observation cannot set accepted data, identity verification, or commitment. The diagnostic domain cites exact application and observation input revisions and a journal prefix. It cannot amend either source to fit a finding.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.

### 4.7 Transaction boundaries

**Application transaction:** atomically commits admitted command, idempotency record, reducer effect, business events, replayable response, resulting state revision, and local outbox metadata.

**Observation transaction:** atomically commits authenticated ingress, producer deduplication, installed-artifact registrations, authorized observations, gap/conflict/loss evidence, observation materialization, and local outbox metadata.

**Diagnostic transaction:** atomically registers already installed diagnostic/report bytes, advances the diagnostic-owned revision, records exact input pins, and publishes local metadata.

No transaction spans these boundaries.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#10.1`

### 10.1 Deterministic analysis

Analysis uses only immutable manifest, named prefix, registered referenced evidence, and pinned classifier/registries.

The prefix ends at `analysis_requested`, which fixes diagnostic ID, revision, classifier, requirement registry, and optional fix registry.

No current time, mutable row, network lookup, unjournaled native response, or operator recollection is evidence.

Stages are:

1. Validate configuration and fixture invariants.
2. Establish completeness and scoped validity.
3. Join actions, requests, validations, transitions, claims, exposures, timings.
4. Evaluate authoritative postconditions.
5. Identify first unmet contract and downstream reachability.
6. Produce typed findings.
7. Render JSON and readable output from the same object.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#10.11`

### 10.11 Summaries and diagnostic domain

`ApplicationSummary` contains goal, as-of journal sequence, predicates, commitment references, and confirmation references.

Goal is completed, not completed, unknown, or inapplicable. The as-of sequence is not the reducer state revision.

`ObservationSummary` contains opened/closed references, closure reason, lifecycle references, containment references, and late evidence.

`SessionDiagnosticValue` contains diagnostic ID, analysis revision, diagnostic artifact, input prefix, application/observation input pins, classifier pin, and replay receipts.

A new replay receipt may advance the diagnostic domain without modifying the selected diagnostic.

Readers compare input pins with current source pins and display staleness.

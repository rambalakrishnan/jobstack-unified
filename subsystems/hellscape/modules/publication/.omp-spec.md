## Invariants & Test Assertions
### Invariants
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-REVISION]**: A domain revision is a complete immutable snapshot, not a patch. revision=previous_revision+1 at the owner. The first revision is 1. The key (entity, domain, revision) identifies exactly one content digest. Identical retries are idempotent; different bytes under that key are an integrity conflict. Stale expected revisions or lease epochs cannot commit.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.
- **[OWD-VIEW]**: A LogicalRow contains every declared domain slot and an exact version vector. Each nonzero slot embeds the complete domain document whose artifact digest and installation receipt it names. A zero slot means no publication in this view, or an explicitly inapplicable manual axis. Readers obtain one complete immutable row root.
- **[OWD-SEAL]**: A seal names a state and pins all domain revisions selected in a named read view. Its journaled seal-selection event pins the domain document digests and publication receipts before the resulting LogicalRow is registered. The row's input prefix includes that selection event, not its own later artifact-registration event.
- **[OWD-ARCHIVE]**: Archive payload_json is the entire previous LogicalRow, including its registration, all domain fields, reasoned nulls, publication receipts, and seal vector. It is not a changed-field diff, crawler-only row, hash list, or lookup of the latest downstream record.
- **[OWD-RETENTION]**: A live replacement pins its archive root and every transitive immutable dependency. A retained later archive containing that replacement's backward link also keeps the earlier archive alive. Publishing a newer job revision, deleting a cache entry, or passing a TTL cannot release those dependencies.
- **[OWD-ATTEMPT]**: Attempt slots contain the exact lifecycle AxisRevision publications. Their outer slot revision equals the embedded axis revision; the axis, attempt identity, commission digest, owner_domain, and writer_id match registration and commission. The reconciler writes only report.
- **[OWD-SESSION]**: Hellscape application state is reducer-owned; observation cannot set accepted data, identity verification, or commitment. The diagnostic domain cites exact application and observation input revisions and a journal prefix. It cannot amend either source to fit a finding.
- **[OWD-TIME-PROVENANCE]**: Every measurement retains clock_id, boot_id, origin, censoring, and an exact, bounded, or unavailable estimate. No cross-clock or cross-restart subtraction is permitted. Publication delay cannot be computed by subtracting arbitrary source and destination UTC annotations. Provenance and writer authorization are assigned and checked at ingestion.
- **[LIFE-PUBLICATION]**: Axis revisions are complete immutable publications. The key is (attempt_id, kind, axis, revision); a different value under the same key is an integrity conflict. Each next revision is previous_revision + 1. Only the owner-local revision check and journal commit are atomic. Publication to readers is asynchronous and cannot require another owner's transaction, acknowledgement, or payload serialization.
- **[LIFE-EVIDENCE]**: The journal is the source of truth. Every publication cites its supporting prefix and source evidence; it is itself registered after its bytes exist. Do not put the publication's own registration event or digest inside its derivation inputs. Imported evidence must be registered locally with its original scope and trust, not promoted by the act of import.

### 5.6 OWD registrations and revisions

Session registration contains record/version, registration ID, session entity key, complete `SessionIdentity`, complete `SessionOwners`, evidence prefix, and support.

`SessionIdentity` contains run ID, primary journal ID, manifest artifact, fixture-build pin, practice attempt, execution descriptor, and optional job-content artifact.

Session owners are application/origin, observation/observer, and diagnostic/analyzer. Each has source ID, writer ID, distinct owner domain, and publication policy.

Every `DataDomainRevision` contains:

- Record/version.
- Entity.
- Registration digest.
- Domain.
- Owner domain.
- Writer ID.
- Revision and previous revision.
- Evidence prefix/support.
- Complete typed value.

Revision starts at 1 and advances by exactly one. Identical retries are idempotent; changed bytes under the same revision key conflict.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#5.7`

### 5.7 Asynchronous publication

Publication consists of:

1. Owner-local durable effect.
2. Complete immutable domain document.
3. Durable document installation and registration.
4. Outbox enqueue.
5. Asynchronous transfer.
6. Source, identity, lineage, reference, and checksum verification.
7. Complete installation in the receiving view.
8. Atomic pointer advance.
9. Publication receipt.

Failures before pointer advance leave the previous complete revision visible.

Reordered delivery cannot roll the pointer backward. Skipped visible revisions require verified lineage.

`PublicationReceipt` retains receipt/entity/registration/view/publisher identities, domain, revision, document, superseded pin, observed owner head or Missing, source prefix, installation time, publication reference, and publication-delay measurement.

Publication delay is unavailable or bounded when compatible clocks are absent.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#5.8`

### 5.8 LogicalRow and seals

A session `LogicalRow` contains record/version, entity, registration digest, complete registration, all three domain slots, and seal.

Published slots contain revision, document artifact, publication reference, and complete snapshot.

Unpublished slots contain revision zero and Missing. They cannot erase previously published history.

Session seals are:

- `session_admitted`
- `observation_closed`
- `diagnostic_published`
- `evidence_updated`

A seal contains ID, name, view, exact three-domain version vector, time, input prefix, and support.

The selection event precedes the row’s registration. A row never cites its own future registration.

### 11.5 Archive representation

A retained complete session archive uses OWD’s:

- `ArchiveStorageManifest`: encoding, version, entity, registration artifact, all domain slots, seal.
- `ArchiveRecord`: record/version, root artifact, storage manifest, complete expanded `LogicalRow`.

The root hashes the storage manifest, not the expanded wrapper.

Expansion loads immutable local extents and reproduces the complete row, including Missing values and exact domain revisions. It does not query mutable peers.

Job fetch-key replacement is not a Hellscape operation. If imported job archives are retained as fixture inputs, their original completeness and retention semantics remain intact.

## Invariants & Test Assertions
### Invariants
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[EK-CLAIMS]**: Preserve claim source, semantic scope, receipt time, and knowledge boundary. None, protocol acknowledgement, HTTP success, and execution completion do not establish application commitment. Authentication and correlation are independent checks. A valid signature with a trace mismatch remains authenticated but not reliably correlated to the claimed attempt.
- **[LIFE-SOURCE-CHECKS]**: Verify source identity and attempt correlation independently. Preserve trace mismatch separately from authentication. An authenticated but uncorrelated message remains evidence of receipt, not an accepted claim/fact for an arbitrary attempt. Strong alternate correlation may establish the attempt despite a trace defect, but must be explicit and evidenced.
- **[LIFE-ORIGIN]**: An application fact must identify the commissioned origin, candidate, job, and attempt, and cite verified source and correlation evidence under the pinned origin policy. A local fixture fact cites its transaction; a production fact cites an actual verified origin receipt. HTTP 200, a submit click, a subject result, or an operator assertion alone is insufficient.
- **[EXT-NORMALIZE]**: Retain exact native bodies before normalization. Authenticate source and correlate to the attempt independently. Mismatched/unknown correlation or unverified source yields no accepted execution claims. Trace mismatch may coexist with independently evidenced alternate correlation.
- **[EXT-AUTHORITY]**: Derive caller identity and grants from authenticated channel registration. Authorize verb, connector, subject, task scope, account/runtime access, artifacts, and control target. IDs and digests are not bearer authority. Application credentials do not grant connector control access.

### 4.6 Imported evidence

A registered source-event import contains:

- Complete original `JournalEnvelope`.
- Artifact reference to its exact canonical bytes.
- Source manifest artifact.
- Source prefix.
- Source authentication/correlation checks.
- Import-policy pin.

The outer import event has importer provenance and observation assertion kind. It does not become an application effect.

Verification covers:

- Source manifest and chain.
- Producer registration.
- Kind/version authorization.
- Owner domain.
- Run/session/attempt correlation.
- Referenced bytes.
- Supporting reference closure.

Every nested artifact appears in `artifact_refs`.

Diagnostics cite the local import and preserve the original source authority. Import does not turn a manual note, connector claim, or historical event into an origin fact.

Identical imports deduplicate. Conflicting bytes under the same source identity create an integrity incident.

### 8.11 SourceChecks and normalization

Source checks retain:

- Authentication: verified, failed, unknown.
- Correlation: matched, mismatched, unknown.
- Trace correlation: matched, mismatched, not observed, inapplicable.
- Verification-policy pin.
- Actual matching-input names.
- Evidence.

Accepted claims require verified source and matched attempt correlation.

Trace mismatch remains visible even when alternate correlation succeeds.

Unverified/uncorrelated messages retain raw bytes but produce no accepted normalized claims.

Native nulls, malformed bodies, unsupported shapes, explicit unknown, missing fields, and conflicting responses remain distinct.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#14.4`

### 14.4 Late-evidence truth cases

| Close-time evidence | Later evidence | Required interpretation |
|---|---|---|
| Outcome unknown | Commitment | Compatible uncertainty |
| Entire-attempt no-commit claim | Verified commitment | Contradiction |
| Stopped claim only | Commitment | No automatic no-commit contradiction |
| No side effect observed | No termination evidence | Indeterminate execution |
| Authenticated callback, unknown correlation | Terminal-looking body | Receipt evidence, not accepted attempt claim |
| Trace mismatch, strong alternate correlation | Verified matching run/attempt evidence | Accepted claim with trace defect retained |
| Fixture sealed after no commit | Later telemetry says submitted | Telemetry cannot manufacture commitment |
| Commitment before close, rendering tail lost | No render receipt | Committed application; rendering unknown |

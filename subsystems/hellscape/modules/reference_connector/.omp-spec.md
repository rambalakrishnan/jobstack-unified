## Invariants & Test Assertions
### Invariants
- **[EXT-SURFACE]**: Recognize exactly the nine versioned verbs. The shared request surface is task-shaped and browser-agnostic. No shared Page, ElementHandle, selector engine, DOM node handle, or synchronous browser primitive is defined here. Native input formats are mapping artifacts, not a cross-browser API.
- **[EXT-DESCRIBE]**: Pin a descriptor to one subject/version/configured mode/interface surface. A new subject version starts unknown on every capability until its own evidence establishes another availability. Neither presence nor absence inherits. Documentation can support a declaration, not a run-success result.
- **[EXT-DECLARE-NOT-ASSESS]**: The connector declares capabilities, mappings, observations, and source claims. It does not emit qualification, requirement satisfaction, or an authoritative application-success flag. Consumer assessment remains separate from capability availability and opportunity.
- **[EXT-TASK]**: Match the full task, scope, permissions, observation policy, assistance, and selected subject to the admitted manifest. Application work additionally matches its immutable commission, including kind and lineage. Manual commissions are not dispatchable through this contract.
- **[EXT-PREPARE]**: Prepare is non-executing. Validate already supplied task data, plan, dependencies, mappings, grants, and declared limits without visiting the target, testing authentication, resetting context, invoking a planner, or secretly improving the plan. Record the native serialization and subject-facing task independently.
- **[EXT-PREPARATION-PIN]**: A preparation is immutable and names the exact descriptor, subject, mapping, full task, delivered task, intended native request, runtime-access references, and limitations. Start accepts that preparation digest, including all concerns requiring acceptance, under actual task authority.
- **[EXT-START]**: Before wire delivery, durably commit the local handle, immutable request binding, idempotency association, and dispatch intent under owner-local fencing. Start returns a local receipt without awaiting task completion. A native run ID is attached only in later source-backed observations.
- **[EXT-IDEMPOTENCY]**: For mutating/collecting calls, (authenticated principal, connector_id, request_id) identifies one command. Same command and identical request returns its retained receipt without another effect; conflicting content under that key is rejected. Describe and Observe are read calls whose responses may reflect newer evidence.
- **[EXT-RESUME]**: Resume requires a new command identity, the existing logical idempotency key/handle, explicit recovery authority, and an evidenced native checkpoint or idempotency contract for the same request and context. It preserves the same logical dispatch and journals each additional delivery.
- **[EXT-CLOSE]**: Closing a connection, ending observation, requesting native cancellation, releasing context, and containment are separate operations/effects. end_observation=true stops new workflow commands and starts the commissioned bounded drain/finalization; false closes only the selected native transport. Neither setting implies a cancel request.
- **[EXT-CONTROLS]**: Every control operation has a scoped authorization and immutable observations. requested records a request attempt, acknowledged records a verified response, and effect_observed requires effect evidence. A subject's confirmed-stop report is still a subject claim.
- **[EXT-BOUNDS]**: Enforce finite local call, queue/observation, drain, cancellation-wait, and cleanup-wait bounds using registered local monotonic clocks. Admission and observation buffering are bounded; rejected work is not silently lost. An accepted queued task consumes its active observation budget.
- **[EXT-STATE-POLICY]**: Browser-state and framework-learning-state requests remain separate. Prepare records their mapping and limitations; actual realization is journaled after Start. An opaque context reference is not a Page or DOM handle and grants no authority by itself.
- **[EXT-EVIDENCE]**: ObservationItem copies an already journaled, registry-validated projection. Its metadata must match the referenced event. Nested claims, control observations, and artifact slots cite earlier supporting events, not themselves. Register/import source evidence before citing it.
- **[LIFE-IDEMPOTENCY]**: The commissioning idempotency key is scoped to the commissioning principal and immutable attempt request. Same key and request returns the same local attempt/handle; changed content under the key is rejected. Repeated Start does not launch a second logical execution.
- **[LIFE-CONTROLS]**: RequestNativeCancel, CloseObservationConnection, ReleaseNativeContext, and Contain are separately evidenced operations. A request is not an acknowledgement; acknowledgement is not an observed effect. A stop claim is retained as a subject claim, not upgraded to a no-commit fact.

### 8.3 Descriptor and capability fields

`ConnectorDescriptor` contains record/version, connector ID/version, build pin, binding pin, subject, capability descriptor, nine operation mappings, task mappings, observation channels, action grounding, execution substrate, limits, budget-accounting pin, and evidence prefix.

Each operation mapping contains operation, implementation, native contract, capability references, evidence, and limitations.

Implementation is connector-local, native-mapping, or unmapped. Handler existence does not establish native support.

Each task mapping contains task type, input form, mapping pin, planning owner, recovery owner, and limitations.

Minimum capability IDs:

- `native_goal_task`
- `native_plan_execution`
- `native_cancel`
- `native_context_release`
- `native_artifact_retrieval`
- `native_revision`
- `native_dom_access`
- `browser_state_isolation`
- `browser_state_persistence`
- `learning_state_control`

Configured limits retain maximum call wait, observation items, request bytes, response bytes, artifact chunk bytes, queued tasks, and active tasks.

These are declarations, not measured capacity.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#8.8`

### 8.8 Start and idempotency

`StartRequest` contains preparation reference, logical idempotency key, accepted concern IDs, authorization references, and recovery.

A preparation reference contains ID, artifact, and registration reference.

A handle reference contains connector ID and local handle.

`ConnectorHandle` contains record/version, handle reference, preparation reference, scope, logical key, and creation time.

`StartResult` contains kind, disposition, complete handle, handle artifact, and receipt reference.

Dispositions are locally accepted, existing handle, or authorized resume.

Before native delivery, the connector durably records handle, immutable request binding, logical key, and dispatch intent.

Command idempotency uses authenticated principal, connector ID, and request ID. Logical execution idempotency additionally uses the Start key and commission.

Changing request IDs, callers, keys, or executors cannot give one commission a second logical execution.

Resume requires existing handle/key, checkpoint artifact, evidenced native resume contract, recovery authority, same context/request, and open observation. It cannot repeat completed side effects.

#### Reference: `seam-mappings/hellscape-seam-mapping.md#8.12`

### 8.12 ControlObservation

Every control record contains:

- Control-event ID and operation ID.
- Operation and target scope.
- Disposition.
- Time.
- Authorization reference.
- Capability reference or Missing.
- Opportunity.
- Request/response references.
- Response checks.
- Native claim references.
- Effect references.
- Known affected attempts.
- Measurements.
- Limitations.

Dispositions are not requested, unsupported, requested, acknowledged, effect observed, or unknown.

Cancel targets native execution; close targets observation connection; release targets native context; containment targets fixture authority, local process, deployment slot, or harness resources.

Acknowledgement requires verified response evidence. Effect-observed requires independent effect evidence.

`end_observation=false` closes only the native observation transport. `true` additionally begins bounded local finalization. Neither implies cancellation.

Release failure cannot silently trigger containment.

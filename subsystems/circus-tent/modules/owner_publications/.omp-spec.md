## Invariants & Test Assertions
### Invariants
- **[LIFE-AXES]**: Exactly one authority role owns each of the five axes. Each applicable axis has exactly one bound publication writer. A writer may publish only its axis and must preserve the identity of its authoritative source. A report writer must not hold execution/application write authority. No whole-attempt status or multi-axis update command is defined here.
- **[LIFE-PUBLICATION]**: Axis revisions are complete immutable publications. The key is (attempt_id, kind, axis, revision); a different value under the same key is an integrity conflict. Each next revision is previous_revision + 1. Only the owner-local revision check and journal commit are atomic. Publication to readers is asynchronous and cannot require another owner's transaction, acknowledgement, or payload serialization.
- **[LIFE-EVIDENCE]**: The journal is the source of truth. Every publication cites its supporting prefix and source evidence; it is itself registered after its bytes exist. Do not put the publication's own registration event or digest inside its derivation inputs. Imported evidence must be registered locally with its original scope and trust, not promoted by the act of import.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-REVISION]**: A domain revision is a complete immutable snapshot, not a patch. revision=previous_revision+1 at the owner. The first revision is 1. The key (entity, domain, revision) identifies exactly one content digest. Identical retries are idempotent; different bytes under that key are an integrity conflict. Stale expected revisions or lease epochs cannot commit.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.
- **[OWD-VIEW]**: A LogicalRow contains every declared domain slot and an exact version vector. Each nonzero slot embeds the complete domain document whose artifact digest and installation receipt it names. A zero slot means no publication in this view, or an explicitly inapplicable manual axis. Readers obtain one complete immutable row root.
- **[OWD-SEAL]**: A seal names a state and pins all domain revisions selected in a named read view. Its journaled seal-selection event pins the domain document digests and publication receipts before the resulting LogicalRow is registered. The row's input prefix includes that selection event, not its own later artifact-registration event.
- **[OWD-ATTEMPT]**: Attempt slots contain the exact lifecycle AxisRevision publications. Their outer slot revision equals the embedded axis revision; the axis, attempt identity, commission digest, owner_domain, and writer_id match registration and commission. The reconciler writes only report.

| Axis | Semantic authority | Circus Tent connector permission |
|---|---|---|
| `dispatch` | Connector | Bound publication writer |

### 14.2 Axis publication

`AxisRevision` contains `record_type: attempt_axis_revision`, lifecycle `schema_version`, `attempt`, `commission_digest`, `axis`, `owner_domain`, `writer_id`, `revision`, `previous_revision`, `evidence_prefix`, `evidence_refs`, `value`.

`LifecyclePublicationReference` contains lifecycle `schema_version`, `attempt`, `commission_digest`, `axis`, `revision`, `owner_domain`, `content`, `registration_ref`. Connector axes are restricted to dispatch, observation, execution.

### 14.6 Reports and snapshots

`ReportValue` contains `state`, `coverage`, `inputs`, `evaluator`, `comparisons`, `issues`, `limitations`, `diagnostic`.

`ReportInputPins` names dispatch, observation, execution, application. Each `DomainPin` contains `revision` and `record_digest`; zero means unpublished with missing digest.

`ClaimComparison` contains `claim_id`, `assertion_id`, `claim_ref`, `fact_ids`, `fact_refs`, `result`, `temporal_relation`, `rationale`, `limitations`.

Result is consistent, contradicted, not-comparable, or indeterminate. `TemporalRelation` contains relation, basis, evidence refs; receipt order alone does not establish occurrence order.

`ReconciliationIssue` contains `kind`, `detail`, `evidence_refs`; kinds are origin-fact conflict, subject-claim conflict, insufficient evidence, incomparable scope, untrusted observation, mapping error, multiple commitments, using schema spellings.

Rules:

- Any proved contradiction makes report contradicted.
- Complete comparisons without contradiction yield reconciled.
- Unresolved comparison yields reasoned missing state.
- No applicable claims yields inapplicable coverage, not success.
- Execution completion without application assertion is narrowly not-comparable.
- Outcome-unknown is compatible with later commitment.
- Entire-attempt no-commit is contradicted by valid commitment.
- Boundary-scoped assertions require actual temporal/causal evidence.

`AttemptSnapshot` contains `record_type`, `schema_version`, `attempt`, `commission`, `commission_digest`, `input_prefix`, all five axis slots, and `seal_point`.

`SealPoint` contains `seal_id`, `name`, `versions`, `evidence_refs`; name is commissioned, observation-closed, or evidence-updated using schema spellings. `VersionVector` contains all five revisions.

`UnpublishedAxis` is revision zero plus `Missing`. It cannot erase an existing publication. Report freshness is determined by comparing its input pins with snapshot source pins.

Manual runs bypass the connector; dispatch/execution stay revision zero and inapplicable. Human actions remain manual observations, while verified employer receipts may establish production facts.

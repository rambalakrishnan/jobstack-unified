## Invariants & Test Assertions
### Invariants
- **[EK-ATTEMPT-SCOPE]**: An application attempt has immutable kind at commissioning. A laboratory fixture is practice and held_in. An employer origin is held_out; production requires an employer origin. derived_from references only the same kind. rehearsal_of links practice to production; performance_of links production to practice. These are lineage links, never evidence promotion.
- **[EK-MANUAL]**: Manual execution has no automation subject, connector version, or binding version. It may produce genuine production observations and origin receipts. Human actions and notes retain manual provenance and disclosed assistance. An operator note alone cannot set an authoritative business predicate.
- **[EK-CLAIMS]**: Preserve claim source, semantic scope, receipt time, and knowledge boundary. None, protocol acknowledgement, HTTP success, and execution completion do not establish application commitment. Authentication and correlation are independent checks. A valid signature with a trace mismatch remains authenticated but not reliably correlated to the claimed attempt.
- **[EK-ASSESSMENT]**: Capability, opportunity, and result are independent fields. satisfied or violated requires a valid exposed opportunity, applicable controls, and supporting evidence. native_absence requires a required, evidenced absent native capability in the exact scope, not mere failure to reach a step. Unexposed work is not_exercised; blocked or invalidly controlled work is not_exercised or indeterminate according to what was actually observed.
- **[LIFE-COMMISSION]**: Commission before an authorized automated dispatch. Freeze attempt identity, kind, candidate, job snapshot, target, task, execution configuration, owner bindings, and permissions. The commission must agree with the admitted manifest and be journaled before Start can cause a native request. Changing the subject version, target, kind, or task creates a new attempt.
- **[LIFE-AXES]**: Exactly one authority role owns each of the five axes. Each applicable axis has exactly one bound publication writer. A writer may publish only its axis and must preserve the identity of its authoritative source. A report writer must not hold execution/application write authority. No whole-attempt status or multi-axis update command is defined here.
- **[LIFE-PUBLICATION]**: Axis revisions are complete immutable publications. The key is (attempt_id, kind, axis, revision); a different value under the same key is an integrity conflict. Each next revision is previous_revision + 1. Only the owner-local revision check and journal commit are atomic. Publication to readers is asynchronous and cannot require another owner's transaction, acknowledgement, or payload serialization.
- **[LIFE-EVIDENCE]**: The journal is the source of truth. Every publication cites its supporting prefix and source evidence; it is itself registered after its bytes exist. Do not put the publication's own registration event or digest inside its derivation inputs. Imported evidence must be registered locally with its original scope and trust, not promoted by the act of import.
- **[LIFE-DISPATCH]**: Prepare is non-executing. Before the first native delivery, durably allocate the connector-local handle and record the intended request digest, idempotency key, and dispatching transition. A native run ID is attached only when actually received and correlated. Local Start acknowledgement is not native acceptance; native acceptance is not execution completion.
- **[LIFE-CLOSE]**: Active observation, transport connection, native execution, application mutation authority, and native context lifetime are distinct. On the local active deadline or end request, stop issuing workflow commands, record native-cancel availability and any attempt, record transport closure, and drain effects/evidence only within the commissioned bound.
- **[LIFE-CLAIMS]**: Execution publications contain only faithfully mapped, source-attributed claims from the commissioned subject/version. Preserve raw responses, mapping versions, declared scope, original times when available, and receipt times. An absent state is Missing, not an invented subject claim of unknown. Explicit unknown remains a valid subject claim.
- **[LIFE-ORIGIN]**: An application fact must identify the commissioned origin, candidate, job, and attempt, and cite verified source and correlation evidence under the pinned origin policy. A local fixture fact cites its transaction; a production fact cites an actual verified origin receipt. HTTP 200, a submit click, a subject result, or an operator assertion alone is insufficient.
- **[LIFE-SOURCE-CHECKS]**: Verify source identity and attempt correlation independently. Preserve trace mismatch separately from authentication. An authenticated but uncorrelated message remains evidence of receipt, not an accepted claim/fact for an arbitrary attempt. Strong alternate correlation may establish the attempt despite a trace defect, but must be explicit and evidenced.
- **[LIFE-RECONCILE]**: The reconciler reads pinned execution claims and origin facts and writes only report. Compare propositions at their actual scope and knowledge boundary. A stopped claim alone does not assert that an already dispatched origin transaction cannot commit.
- **[LIFE-REPORT-COVERAGE]**: Every claim and application assertion in the pinned execution publication is accounted for by a comparison or an explicit scope/uncertainty limitation. Any proved contradiction makes report.state contradicted, even if other comparisons remain incomplete. With no contradiction, complete comparisons yield reconciled; unresolved comparisons yield Missing with reason. No applicable subject claims yield not_applicable coverage, not a fabricated successful comparison.
- **[LIFE-LATE-EVIDENCE]**: Evidence received after observation closure is appended at the current journal head. Publish new owner revisions and a new report over new input pins; preserve every prior seal, publication, and diagnostic. A current snapshot may legitimately contain newer facts than its latest report used.
- **[LIFE-LINEAGE]**: kind is immutable. Laboratory fixtures are practice and held_in; employer origins are held_out and production requires an employer origin. derived_from is same-kind and acyclic. rehearsal_of points from practice to an already commissioned production identity; performance_of points from production to an already commissioned practice identity.
- **[LIFE-MANUAL]**: Manual mode requires no automation subject, native run ID, connector version, or native binding version. Its dispatch and execution slots stay at revision zero with not_applicable. The recorder owns observation and journals human actions with manual provenance.
- **[LIFE-TIME]**: All measured durations use Measurement with clock_id, boot_id, origin, discriminated estimate, and censoring. Endpoint subtraction requires one registered clock/boot/origin and ordered endpoints; exact zero is valid. UTC annotations and receipt order cannot establish cross-clock occurrence order. Opaque origin revisions are not lexically ordered as timestamps.

### 6.4 Dispatch transitions and fields

| From | Allowed next |
|---|---|
| Unpublished | `not_started`, `prepared`, `rejected` |
| `not_started` | `prepared`, `rejected` |
| `prepared` | `dispatching`, `rejected` |
| `dispatching` | `accepted`, `rejected`, `uncertain` |
| `uncertain` | `uncertain`, `accepted`, `rejected` |
| `accepted` | `accepted` |
| `rejected` | `rejected` |

`DispatchValue` contains `state`, `local_handle`, `native_run_id`, `request_digest`, `delivery_refs`, `acceptance_refs`, `recovery_authorization_refs`, and `reason`.

- Prepared requires request digest.
- Dispatching/accepted/uncertain require handle, digest, and delivery evidence.
- Accepted requires correlated native acceptance/result evidence.
- Not-started has no native ID, delivery refs, or acceptance refs.
- Rejection after possible delivery requires evidence of non-acceptance.
- Same-state revisions add evidence, never authorize another logical execution.

A native preflight failure may still prove request acceptance. HTTP 429 proves rejection only if the pinned native semantics establish non-acceptance.

### 14.1 Commission

`AttemptContext` contains `attempt_id`, `kind`, `target_class`, `target_id`, `evaluation_partition`, `rehearsal_of`, `performance_of`, `derived_from`.

- Laboratory fixture: practice, held-in.
- Employer origin: held-out; production requires employer origin.
- Derived-from links are same-kind and acyclic.
- Practice rehearsal links and production performance links are lineage, not evidence promotion.

`AttemptCommission` contains:

`record_type`, lifecycle `schema_version`, `kernel_version`, `commission_id`, `run_id`, `journal_id`, `manifest_hash`, `admission_ref`, `commissioned_by`, `commissioned_at`, `attempt`, `candidate_id`, `candidate_profile`, `job`, `selection_evidence`, `task`, `task_semantic_hash`, `initial_materials`, `execution`, `owners`, `idempotency_key`, `authorization_refs`, `recovery_review_refs`, `observation_policy`, `origin_policy`.

All copied task, subject, scope, key, policy, and identity values must match admission. Subject/version/target/task/kind changes create a new attempt.

`JobReference` contains `job_id`, `source_target`, `source_job_id`, `snapshot`. Company/title matching is not application identity.

`OwnerBindings` contains exactly dispatch, observation, execution, application, report. Each `AuthorityBinding` contains `role`, `source_id`, `writer_id`, `owner_domain`, `publication_policy`. Actual authorization verifies these declarations.

#### Reference: `seam-mappings/circus-tent-seam-mapping.md#143-observation-policy-and-states`

### 14.3 Observation policy and states

`ObservationPolicy` contains `active_limit`, `drain_limit`, `native_cancel_wait_limit`, `cleanup_wait_limit`, `fixture_close_action`.

Each `DurationLimit` is `kind: exact`, `unit: ms`, finite nonnegative `value`; zero is immediate. No universal durations are introduced. Employer origins require fixture-close action inapplicable.

| From | Allowed next |
|---|---|
| Unpublished | `not_opened`, `open`, `closed` |
| `not_opened` | `open`, `closed` |
| `open` | `open`, `draining`, `closed` |
| `draining` | `draining`, `closed` |
| `closed` | `closed` |

`ObservationValue` contains `state`, `window_id`, `opened_at`, `active_deadline`, `drain_started_at`, `drain_deadline`, `closed_at`, `close_reason`, `at_close`, `control_observations`, `late_evidence_refs`, `measurements`.

Close reasons are `normal_completion`, `operator_stop`, `local_deadline`, `translation_failure`, `launch_failure`, `subject_terminal`, `connection_lost`, `infrastructure_interruption`.

Open/draining requires actual open time and active deadline. Draining requires drain coordinates and reason. Closed requires close time, reason, and snapshot. Before closure, close time/snapshot are inapplicable.

Closed-first is allowed for early failure. Closed-to-closed may add evidence but cannot rewrite the original boundary or reopen commands.

#### Reference: `seam-mappings/circus-tent-seam-mapping.md#144-close-snapshot`

### 14.4 Close snapshot

`CloseSnapshot` contains `closure_id`, `boundary_ref`, `known_versions`, `execution_knowledge`, `execution_evidence_refs`, `application_knowledge`, `application_evidence_refs`, `limitations`.

`known_versions` pins dispatch, execution, application, report, excluding the closing publication.

Execution knowledge: running, terminal, unknown, not-applicable. Application knowledge: committed, not-committed, unknown.

Silence yields unknown. Earlier running or as-of absence does not automatically establish the state at closure. Restart records interruption; it does not invent cross-boot elapsed time or backdate closure.

#### Reference: `seam-mappings/circus-tent-seam-mapping.md#145-origin-facts`

### 14.5 Origin facts

The connector only collects receipt observations. A separately authorized recorder verifies source, meaning, candidate/job/attempt correlation, and origin policy.

`OriginFact` contains:

`fact_id`, `origin_id`, `candidate_id`, `job_id`, `state`, `coverage`, `boundary_ref`, `origin_application_id`, `origin_revision`, `receipt`, `verification_kind`, `source_checks`, `authority_seal_ref`, `occurred_at`, `received_at`, `evidence_refs`.

- State: `committed` or `not_committed`; unknown observations are not negative facts.
- Coverage: `at_boundary` or `final_for_attempt`.
- Production verification: `verified_origin_receipt`.
- Practice local transaction: `local_origin_transaction`.
- Final negative fact requires origin-owned finality evidence.
- Confirmation rendering and commitment remain distinct.
- Later rejection, withdrawal, or job closure does not erase historical commitment.

`ApplicationValue` contains cumulative nonempty `facts`. Conflicts and multiple commitments remain visible.

#### Reference: `seam-mappings/circus-tent-seam-mapping.md#146-reports-and-snapshots`

### 14.6 Reports and snapshots

`ReportValue` contains `state`, `coverage`, `inputs`, `evaluator`, `comparisons`, `issues`, `limitations`, `diagnostic`.

`ReportInputPins` names dispatch, observation, execution, application. Each `DomainPin` contains `revision` and `record_digest`; zero means unpublished with missing digest.

`ClaimComparison` contains `claim_id`, `assertion_id`, `claim_ref`, `fact_ids`, `fact_refs`, `result`, `temporal_relation`, `rationale`, `limitations`.

Result is consistent, contradicted, not-comparable, or indeterminate. `TemporalRelation` contains relation, basis, evidence refs; receipt order alone does not establish occurrence order.

`ReconciliationIssue` contains `kind`, `detail`, `evidence_refs`; kinds are origin-fact conflict, subject-claim conflict, insufficient evidence, incomparable scope, untrusted observation, mapping error, multiple commitments, using schema spellings.

Rules:

- Any proved contradiction makes report contradicted.
- Complete comparisons without contradiction yield reconciled.
- Unresolved comparison yields reasoned missing state.
- No applicable claims yields inapplicable coverage, not success.
- Execution completion without application assertion is narrowly not-comparable.
- Outcome-unknown is compatible with later commitment.
- Entire-attempt no-commit is contradicted by valid commitment.
- Boundary-scoped assertions require actual temporal/causal evidence.

`AttemptSnapshot` contains `record_type`, `schema_version`, `attempt`, `commission`, `commission_digest`, `input_prefix`, all five axis slots, and `seal_point`.

`SealPoint` contains `seal_id`, `name`, `versions`, `evidence_refs`; name is commissioned, observation-closed, or evidence-updated using schema spellings. `VersionVector` contains all five revisions.

`UnpublishedAxis` is revision zero plus `Missing`. It cannot erase an existing publication. Report freshness is determined by comparing its input pins with snapshot source pins.

Manual runs bypass the connector; dispatch/execution stay revision zero and inapplicable. Human actions remain manual observations, while verified employer receipts may establish production facts.

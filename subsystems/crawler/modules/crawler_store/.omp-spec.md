## Invariants & Test Assertions
### Invariants
- **[EK-JOURNAL]**: An acknowledged event is durably appended. Sequences are contiguous and strictly increasing within a journal, beginning at 1. The first event is manifest_admitted and pins the complete immutable manifest. All subsequent events name the same run, journal, and manifest digest. Events are never edited, deleted, resequenced, or backdated into an earlier prefix.
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-OBSERVATION]**: Producer IDs identify one sequence lifetime. Deduplicate identical (producer_id, producer_sequence) deliveries without duplicating effects. Conflicting content under that key is an integrity incident, not last-write-wins. Journal gaps, overflow, loss, flush receipts, and producer closure. A closed HTTP connection is not producer completeness or execution termination.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-REVISION]**: A domain revision is a complete immutable snapshot, not a patch. revision=previous_revision+1 at the owner. The first revision is 1. The key (entity, domain, revision) identifies exactly one content digest. Identical retries are idempotent; different bytes under that key are an integrity conflict. Stale expected revisions or lease epochs cannot commit.

### 16.5 Atomic stage effects

- **Extract:** Listings, observation packet, exact occurrences, coverage delta, certified cursor boundary, and audit.
- **Snippet classification:** Genuine result/application or bypass evidence, listing transition, lease release.
- **Dispatch:** Work materialization, listing delegation, lineage, lease release, audit.
- **Fetch:** Detail materialization/reuse, work completion/failure, lineage, membership if eligible, audit.
- **Description classification:** Genuine/application or bypass, detail/listing transition, semantic evidence, membership, lease release.
- **Finalize:** Four-field synthesis, identity protocol, detail/listing completion, membership, audit.
- **Failure/reclamation:** Fence/clear, once-only retry, pending/terminal route, terminal dead letter, audit.

No database transaction spans network, model inference, signal emission, or human waiting.

### 20.4 Exact Contract 04 records

`DataDomainRevision` contains record/version, entity, registration digest, domain, owner domain, writer ID, revision, previous revision, evidence prefix, evidence refs, and complete value.

`PublicationReceipt` contains receipt identity, entity/registration/view/publisher, domain/revision/document, superseded pin, observed owner head or Missing, source prefix, installation time, publication ref, and measured/bounded/unavailable publication delay.

Installation validates complete immutable bytes before atomic pointer advance. Reordering cannot regress the pointer. Skipping visible revisions requires verified lineage. Identical delivery returns the existing receipt.

`LogicalRow` contains entity, complete registration and digest, every domain slot, and seal point. A published slot contains revision, document reference, publication reference, and complete snapshot. Zero means unpublished/inapplicable, never lost published bytes.

`SealPoint` contains seal ID/name/view, exact version vector, time, input prefix, and support. Selection is journaled before resulting row registration, avoiding self-reference.

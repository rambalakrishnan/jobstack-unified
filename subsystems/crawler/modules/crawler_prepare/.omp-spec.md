## Invariants & Test Assertions
### Invariants
- **[EXT-PREPARE]**: Prepare is non-executing. Validate already supplied task data, plan, dependencies, mappings, grants, and declared limits without visiting the target, testing authentication, resetting context, invoking a planner, or secretly improving the plan. Record the native serialization and subject-facing task independently.
- **[EXT-PREPARATION-PIN]**: A preparation is immutable and names the exact descriptor, subject, mapping, full task, delivered task, intended native request, runtime-access references, and limitations. Start accepts that preparation digest, including all concerns requiring acceptance, under actual task authority.
- **[EXT-TASK]**: Match the full task, scope, permissions, observation policy, assistance, and selected subject to the admitted manifest. Application work additionally matches its immutable commission, including kind and lineage. Manual commissions are not dispatchable through this contract.
- **[EXT-READ-ONLY]**: discover_jobs and extract tasks cannot execute employer/application mutations. HTTP method alone does not determine whether an operation is read-only. The crawler cannot gain application authority through an extraction extension, plan artifact, redirect, or permissive task text.
- **[EXT-STATE-POLICY]**: Browser-state and framework-learning-state requests remain separate. Prepare records their mapping and limitations; actual realization is journaled after Start. An opaque context reference is not a Page or DOM handle and grants no authority by itself.
- **[EXT-BOUNDS]**: Enforce finite local call, queue/observation, drain, cancellation-wait, and cleanup-wait bounds using registered local monotonic clocks. Admission and observation buffering are bounded; rejected work is not silently lost. An accepted queued task consumes its active observation budget.
- **[EK-ATTEMPT-SCOPE]**: An application attempt has immutable kind at commissioning. A laboratory fixture is practice and held_in. An employer origin is held_out; production requires an employer origin. derived_from references only the same kind. rehearsal_of links practice to production; performance_of links production to practice. These are lineage links, never evidence promotion.

- `commission=Inapplicable`

The kernel manifest contains immutable task/configuration artifacts, execution descriptor, build pins, producer registry, event registry, clocks, environment, seed missingness, and source admission.

A crawler service run may use kernel execution mode `service`; its subject is inapplicable. A connector descriptor still identifies its configured native subject/service scope honestly. It does not fabricate an application attempt or browser qualification result.

### 19.4 Preparation and handle fields

`PreparedTask` preserves all required fields: preparation ID, scope, configuration, full task, semantic hash, assistance, planning refs, runtime access, delivered-task artifact/hash, native-request artifact/hash, translation pin, all five budget mappings, concerns, and evidence prefix.

Configuration pins connector ID/version, binding pin, exact subject identity, descriptor artifact, and descriptor evidence.

Runtime access contains purpose, opaque access reference, and authorization refs. It carries no secret bytes or control credentials.

Start accepts preparation reference, logical idempotency key, every required concern acceptance, authorization refs, and either inapplicable recovery or explicit same-handle resume authorization.

`ConnectorHandle` contains record/version, handle reference, preparation reference, scope, idempotency key, and real creation TimePoint. Native IDs arrive later as observations.

Command deduplication uses authenticated principal, connector, and request ID. Logical execution deduplication independently uses Start’s idempotency key bound to immutable preparation. Conflicting content rejects; a lost reply does not justify a fresh key.

Resume needs the existing handle/key, new command identity, recovery authority, and evidenced native checkpoint/idempotency contract. Lease expiry alone is insufficient. Closed/draining observation cannot be reopened.

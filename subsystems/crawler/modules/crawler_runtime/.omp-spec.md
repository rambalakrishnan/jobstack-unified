## Invariants & Test Assertions
### Invariants
- **[EXT-SURFACE]**: Recognize exactly the nine versioned verbs. The shared request surface is task-shaped and browser-agnostic. No shared Page, ElementHandle, selector engine, DOM node handle, or synchronous browser primitive is defined here. Native input formats are mapping artifacts, not a cross-browser API.
- **[EXT-READ-ONLY]**: discover_jobs and extract tasks cannot execute employer/application mutations. HTTP method alone does not determine whether an operation is read-only. The crawler cannot gain application authority through an extraction extension, plan artifact, redirect, or permissive task text.
- **[EXT-BOUNDS]**: Enforce finite local call, queue/observation, drain, cancellation-wait, and cleanup-wait bounds using registered local monotonic clocks. Admission and observation buffering are bounded; rejected work is not silently lost. An accepted queued task consumes its active observation budget.
- **[EXT-FAILURE]**: ConnectorError describes failure to carry out this connector operation, not a composite task outcome. An observed native failed/completed/stopped claim is normal evidence returned by Observe. Local prerequisite and translation errors are not fabricated subject failures.
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-CLAIMS]**: Preserve claim source, semantic scope, receipt time, and knowledge boundary. None, protocol acknowledgement, HTTP success, and execution completion do not establish application commitment. Authentication and correlation are independent checks. A valid signature with a trace mismatch remains authenticated but not reliably correlated to the claimed attempt.
- **[OWD-OWNER]**: Every declared domain has one authenticated logical writer. Entity registration fixes its field set, authority source, writer, storage-domain identity, and publication policy. Temporary workers act through that writer's fenced transition gateway; they do not become additional owners. Each owner_domain is distinct within an entity.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.

### 19.3 Verb behavior

| Verb | Required crawler behavior |
|---|---|
| **Describe** | Return exact connector/build/binding/subject pins, complete capability catalog, nine operation mappings, supported task mappings, channels, grounding/substrate, limits, accounting pin, evidence prefix. No probes, browser start, or task execution |
| **Prepare** | Validate immutable scope, task, declarations, schemas, permissions, budgets, state policy, mappings, supplied planning evidence, and runtime-access grants. Serialize intended native request and delivered task. No target request, auth test, planner execution, context reset, or hidden recovery |
| **Start** | Atomically persist/recover local handle, preparation binding, idempotency association, and dispatch intent before wire delivery; return asynchronously |
| **Observe** | Return registered handle-scoped projections in journal order through a fixed prefix, with bounded wait and explicit cursor semantics |
| **RequestNativeCancel** | Invoke only evidenced native cancellation mapping; otherwise unsupported mapping. Preserve request, acknowledgement, stop claim, effect, and timing independently |
| **CloseObservationConnection** | Close only the connector-owned observation transport. `end_observation=true` stops new workflow delivery and begins bounded local drain; neither operation implies native cancellation |
| **CollectArtifacts** | Inventory or transfer already produced authorized immutable artifacts; no arbitrary path/URL fetch and no task rerun |
| **ReleaseNativeContext** | Use only mapped, authorized context release. No implicit logout, profile purge, global reset, or containment fallback |
| **Contain** | Execute installed versioned policy against authorized resource-registry scope; no arbitrary shell command. Record affected work and unresolved impact |

Every verb has a handler even if native mapping is absent.

Capability catalogs include the shared minimum IDs: native goal task, plan execution, cancel, context release, artifact retrieval, revision, DOM access, browser isolation, browser persistence, and learning-state control. New versions start unknown; inapplicability and absence require evidence. Unsupported mapping is not native absence.

### 20.6 Retention

`RetentionPinRevision` contains pin/owner/writer identities, revision/previous revision, dependent root, archive root, active/released state, release ref, evidence prefix, and support.

Initial pins are active. Dependent and archive identity never change under a pin ID. Release requires evidenced retirement and does not remove other roots’ protection.

Protection is transitive through registration, domains, referenced artifacts, publication/seal evidence, and earlier replacement archives. GC is fenced against concurrent pin creation.

Newer rows, TTL, and cache eviction do not release dependencies. Lost bytes are an integrity incident, not successful GC or permission to reconstruct different content.

### 21.3 Resource and performance contract

Crawler defaults remain deployment declarations:

- Cold worker target 200 MB.
- Warm worker target `(N+1)×130+70` MB.
- Orchestrator target 200 MB.
- Aggregate embedded storage target 100 MB.
- SLM nominal 600 MB–2.5 GB; class targets 1 GB/3 GB.
- Default declared overshoot maximum 25%, with justification.
- SLM batch target 100–200 ms under the reference ≤512-token envelope; not a supplied benchmark.
- Navigation ceilings remain target-wide.
- Default response bound 64 MiB and streaming buffer 1 MiB.
- Queue default 10,000 rows plus explicit byte bound.
- Microbatching at most 1 ms.

Inference runs in a separately bounded process/domain with host admission reserving crawler/storage/OS resources. An SLM-induced crawler OOM invalidates the run, stops claims, and prevents successful completion representation. It is not an ordinary retry.

Pagination orchestration median must be ≤10% of measured network median. Network, bootstrap, downstream inference, explicit admission wait, and synchronous signal blocking are separately measured, not hidden.

Signals contain stage rows in/out, stage latency, queue depth, request overhead, and sink latency. Sink calls hold no session, transaction, completion, or V8 lock. Median sink latency above 100 ms over five minutes marks degraded throughput; a stuck sink cannot recursively emit its own latency.

## Part I — The position

There are four components in scope and a fifth outside the directories.

**The crawler (Stage1 with Rust direction is specified in `2-state-bank-crawler-blueprint.md`.).** Crawls state job bank sites, extracts, classifies, emits a job feed. Originally intended to use Camoufox for stealth on commercial boards; later discovery is that a large subset of the same jobs is available through state sites that scale much better on simpler automation. Current direction is Rust + BrowserOxide, with an Illinois-only first slice. The full spec contains four `INCOMPLETE` markers and nine `ASSUMED` markers; these are backlog, not milestones.

**circus-tent (two bindings. Specified in `4-circus-tent-arch.md`.).** A browser-use framework that fills forms and submits applications. Python bound to Camoufox via Juggler via Playwright Async API. Concepts came from Stagehand (which is TypeScript bound to Chromium via CDP). The owner attempted a Stagehand-to-Camoufox port via Playwright/Juggler and it failed; that failure is now a governing architectural constraint (Part III).

**ringmaster (an isomorphic synthesis of Stagehand into native Rust/BrowserOxide) Like circus-tent, it shall inherit Stagehand's cognitive vocabulary and core primitives observe (Native tree reduction and action candidate identification), act (Hierarchical selector execution, self-healing via LLM, and coordinate fallback), extract (Schema-guided extraction without arbitrary DOM dumps). Like circus-tent, it deviates from Stagehand in two major ways: Instead of operating as an open-ended natural language agent, it takes an explicit, commissioned TaskEnvelope, executes bounded steps under finite budgets, and exposes the 9 standard connector verbs (Describe, Prepare, Start, Observe, etc.). Stagehand has zero awareness of the hostile, idiosyncratic patterns of enterprise job portals; Circus Tent has solved specific ATS problems (Multi-Page Wizard Checkpoints, Dual Upload Engine, Sharding & Session Concurrency, and dHash Localized Container Crops.

**Hellscape (Go direction. Specified in `3-hellscape-blueprint.md`.).** A hostile SPA fixture that presents increasingly difficult form-filling tasks to a browser-use framework and produces a diagnostic document. It is a form-fidelity laboratory, not an applicant-tracking system and not a fake employer. Its purpose is to hammer the framework and produce improvement feedback.

**job-hunter (language TBD, Python and Firebase implementation specified in `6-get-a-job.xml.txt`.).** Consumes the crawler's feed, scores jobs against the capability profile and the eight playbooks in `capability_profile.txt` / `job_search_queries.txt`, commissions applications via circus-tent, tracks attempts. Storage and language are open questions.

**m0-qualification (Python; retired as standalone. Specified in `5-browser-qualification.md`.).** A harness that qualified browser/driver/binary stacks against an evidence discipline: `None` is not success, an acknowledgement is not a semantic success, a harness timeout is not a native timeout, an HTTP 200 is not authentication. m0 dissolves; its discipline becomes enforced conformance suites (Part VII).

The components are each independently shippable. The failure mode to prevent is integration hell arising from contracts that are *derived from* implementations rather than *specified before* them.

## Invariants & Test Assertions
### Invariants
- **[EK-JOURNAL]**: An acknowledged event is durably appended. Sequences are contiguous and strictly increasing within a journal, beginning at 1. The first event is manifest_admitted and pins the complete immutable manifest. All subsequent events name the same run, journal, and manifest digest. Events are never edited, deleted, resequenced, or backdated into an earlier prefix.
- **[EK-ATOMICITY]**: A locally authoritative operation commits its admitted input, idempotency record, authoritative effects, journal events, and replayable response as one owner-local durable effect before acknowledgement. Install referenced artifact bytes durably before that commit. Cross-owner publication remains asynchronous; this rule does not authorize a shared transaction across owners.
- **[EK-HASHES]**: Verify all content digests. At sequence 1, previous_event_hash is Missing(not_applicable). At sequence n>1 it equals event_hash at n-1. JournalPrefix.head_hash equals the event hash at last_sequence. Resolve an EvidenceRef by journal, sequence, event ID, hash, and JSON pointer; all must agree. A hash chain detects changed content but is not authentication.
- **[EK-PROVENANCE]**: The ingestion authority assigns producer identity, provenance, owner_domain, role, assertion_kind, event ID, sequence, receipt time, and hashes using authenticated producer registration and the manifest's event registry. Untrusted callers submit EventSubmission, never JournalEnvelope. Reject submitted server/provenance/authority fields rather than trusting them.
- **[EK-OBSERVATION]**: Producer IDs identify one sequence lifetime. Deduplicate identical (producer_id, producer_sequence) deliveries without duplicating effects. Conflicting content under that key is an integrity incident, not last-write-wins. Journal gaps, overflow, loss, flush receipts, and producer closure. A closed HTTP connection is not producer completeness or execution termination.
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[LIFE-EVIDENCE]**: The journal is the source of truth. Every publication cites its supporting prefix and source evidence; it is itself registered after its bytes exist. Do not put the publication's own registration event or digest inside its derivation inputs. Imported evidence must be registered locally with its original scope and trust, not promoted by the act of import.
- **[EXT-EVIDENCE]**: ObservationItem copies an already journaled, registry-validated projection. Its metadata must match the referenced event. Nested claims, control observations, and artifact slots cite earlier supporting events, not themselves. Register/import source evidence before citing it.
- **[EXT-ARTIFACTS]**: Install immutable artifact bytes durably before journal references. Artifact names and digests resolve only within the authorized handle's retained evidence or declared native retrieval mapping. Do not fetch arbitrary caller URLs or filesystem paths through CollectArtifacts.
- **[OWD-LOCAL-COMMIT]**: Commit an owner's authorized effect, revision advance, and journal evidence atomically within that owner's durability boundary. Do not acknowledge before durability. No owner commit acquires a peer-owned write lock or waits for a peer transaction, acknowledgement, or large-payload serialization.
- **[OWD-PUBLISH]**: Owner durability acknowledgement and installation into a read view are different events. Transfer, validate, and durably install all immutable components before atomically advancing the view's domain pointer. The pointer update is bounded metadata work. Publication cannot expose partially transferred bytes.
- **[OWD-RETENTION]**: A live replacement pins its archive root and every transitive immutable dependency. A retained later archive containing that replacement's backward link also keeps the earlier archive alive. Publishing a newer job revision, deleting a cache entry, or passing a TTL cannot release those dependencies.

### 3.5 Hashing and storage

Structured records use RFC 8785 canonical JSON and SHA-256. Artifact digests cover exact stored bytes. Array order and string contents are preserved.

Redaction creates a new artifact with a journaled derivation. Hash validity does not authenticate a source.

Artifacts are installed durably before referencing events or publications. A record cannot cite its future registration. Known artifact identity survives byte loss; loss is journaled rather than replaced under the old digest.

#### Reference: `seam-mappings/ringmaster-seam-mapping.md#3.6`

### 3.6 Journal submission and envelope

Ringmaster submits `EventSubmission`, never a caller-authored `JournalEnvelope`.

| Submission field | Mapping |
|---|---|
| `producer_sequence` | Monotonic producer-lifetime sequence, or permitted Missing for an unsequenced producer |
| `event_kind` | Manifest-registered kind |
| `event_schema_version` | Registered event version |
| `occurred_at` | Actual source TimePoint or Missing |
| `payload` | Required `data`, `measurements`, `evidence_refs`, `artifact_refs` |

The journal authority assigns and verifies:

- `record_type`, `schema_version`
- `run_id`, `journal_id`, `manifest_hash`
- `journal_sequence`, `event_id`
- `event_kind`, `event_schema_version`
- `role`, `assertion_kind`
- `owner_domain`, `producer_id`, `producer_sequence`, `provenance`
- `evidence_scope`
- `recorded_at`, `occurred_at`
- `causal_refs`, `payload`
- `previous_event_hash`, `event_hash`

Sequence one is `manifest_admitted`; subsequent sequences are contiguous. Duplicate producer sequence with identical content deduplicates; conflicting content is an integrity incident.

Producer gaps, overflow, flush, terminal sequence, closure, and loss are explicit. A closed transport is not producer completeness.

## 18. Lease, recovery, and crash semantics

When Ringmaster uses leased resources, it consumes the exact kernel LeaseRecord, not a worker-authored claim token.

| Lease fields | Mapping |
|---|---|
| `record_type`, `schema_version` | Exact lease record |
| `resource` | owner_domain, entity_type, entity_id of the actual resource |
| `policy` | Owner-specific eligibility/TTL/retry/routing pin |
| `issuer_id`, `authority_epoch` | Actual lease authority and lifetime |
| `entity_revision`, `input_revision`, `generation_id` | Fenced resource/input generation |
| `resource_state`, `eligible_state` | Owner state; claim does not change it |
| `lease_state` | unleased or held |
| `lease_id`, `lease_owner`, `owner_epoch`, `session_epoch` | Current fencing identities |
| `leased_at`, `lease_expires_at` | One registered authority clock/boot |
| `retry_count`, `max_retries_effective`, `last_failure_reason` | Owner retry policy state |
| `journal_prefix`, `evidence_refs` | Supporting durable evidence |

Unleased ownership/time fields are inapplicable. Held records require lease identity, owner, epoch, issue/expiry, compatible state, and applicable session epoch.

Claim atomically checks eligibility and absence of an unexpired lease, advances revision, clears failure reason, and appends evidence. Completion checks lease, expiry, revisions, and epochs. Stale completion has no effect.

Release, expiry, and confirmed-death recovery clear ownership atomically. A failed generation increments retries at most once. Successful completion is not a failed retry.

Authority restart fences its old epoch before reclamation; old/new monotonic offsets are never compared. Reclamation revokes local commit authority, not proof that a worker or employer transaction stopped.

| Crash boundary | Required recovery |
|---|---|
| Before durable Start | No acceptance claim |
| After local admission, before delivery | Recover same handle; deliver only within remaining authority |
| Around native delivery | Preserve uncertainty unless stronger evidence exists |
| After side effect, before local result | Never replay merely to repair journal |
| During artifact install | Do not publish absent bytes |
| After artifact install, before registration | Recover/register under owner policy; no external rerun |
| After registration, before response | Same command returns retained receipt |
| During native owner loss | Fence dependent commands; retain unresolved effects |
| After observation closure | Append late evidence; never reopen window |

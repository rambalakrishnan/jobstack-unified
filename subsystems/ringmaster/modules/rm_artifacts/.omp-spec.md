## Invariants & Test Assertions
### Invariants
- **[EK-ARTIFACTS]**: Citable artifacts are immutable, content-addressed, access-classified, and registered by journal events. Retain bytes while a retained manifest, journal prefix, diagnostic, replay bundle, or archive depends on them. Do not substitute a locator or hash alone for promised archived content.
- **[EK-NULL]**: Every null is Missing(value=null, reason=<one of the six reasons>). Empty arrays mean an established empty collection, not unknown contents. Unknown semantic states remain explicit enums; false and zero are never missing-value sentinels. manual_override requires an authenticated journaled operator decision and preserves the superseded observation.
- **[EXT-ARTIFACTS]**: Install immutable artifact bytes durably before journal references. Artifact names and digests resolve only within the authorized handle's retained evidence or declared native retrieval mapping. Do not fetch arbitrary caller URLs or filesystem paths through CollectArtifacts.
- **[EXT-IDEMPOTENCY]**: For mutating/collecting calls, (authenticated principal, connector_id, request_id) identifies one command. Same command and identical request returns its retained receipt without another effect; conflicting content under that key is rejected. Describe and Observe are read calls whose responses may reflect newer evidence.
- **[EXT-AUTHORITY]**: Derive caller identity and grants from authenticated channel registration. Authorize verb, connector, subject, task scope, account/runtime access, artifacts, and control target. IDs and digests are not bearer authority. Application credentials do not grant connector control access.
- **[OWD-RETENTION]**: A live replacement pins its archive root and every transitive immutable dependency. A retained later archive containing that replacement's backward link also keeps the earlier archive alive. Publishing a newer job revision, deleting a cache entry, or passing a TTL cannot release those dependencies.

### 14.6 CollectArtifacts

Request contains `handle` and selector:

- Inventory: `mode`.
- Named: `mode`, nonempty unique `names`.
- Bytes: `mode`, `digest`, `offset`, positive `max_bytes`.

ArtifactInventory contains `kind`, `handle`, `artifacts`, `coverage`, `evidence_prefix`, `limitations`.

ArtifactSlot contains `name`, `expected_digest`, `content`, `evidence_refs`. Available content matches expected digest. Named requests return exactly requested names, including missing slots.

ArtifactChunk contains `kind`, `handle`, `digest`, `size_bytes`, `offset`, `returned_bytes`, `data_base64`, `chunk_digest`, `end_of_artifact`, `evidence_refs`.

Verify canonical padded base64, lengths, chunk/full digest, bounds, and EOF. Non-EOF successful chunks advance. No arbitrary URL/path retrieval, rerun, or new browser session is allowed to manufacture artifacts.

### 3.5 Hashing and storage

Structured records use RFC 8785 canonical JSON and SHA-256. Artifact digests cover exact stored bytes. Array order and string contents are preserved.

Redaction creates a new artifact with a journaled derivation. Hash validity does not authenticate a source.

Artifacts are installed durably before referencing events or publications. A record cannot cite its future registration. Known artifact identity survives byte loss; loss is journaled rather than replaced under the old digest.

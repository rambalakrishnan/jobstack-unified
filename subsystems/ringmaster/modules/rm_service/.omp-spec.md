ConnectorError contains required:

`kind: connector_error`, `code`, `fault_domain`, `detail`, `operation_delivery`, `retry_guidance`, `retry_after`, `handle`, `evidence_refs`.

## Part I — The position

There are four components in scope and a fifth outside the directories.

**The crawler (Stage1 with Rust direction is specified in `2-state-bank-crawler-blueprint.md`.).** Crawls state job bank sites, extracts, classifies, emits a job feed. Originally intended to use Camoufox for stealth on commercial boards; later discovery is that a large subset of the same jobs is available through state sites that scale much better on simpler automation. Current direction is Rust + BrowserOxide, with an Illinois-only first slice. The full spec contains four `INCOMPLETE` markers and nine `ASSUMED` markers; these are backlog, not milestones.

**circus-tent (two bindings. Specified in `4-circus-tent-arch.md`.).** A browser-use framework that fills forms and submits applications. Python bound to Camoufox via Juggler via Playwright Async API. Concepts came from Stagehand (which is TypeScript bound to Chromium via CDP). The owner attempted a Stagehand-to-Camoufox port via Playwright/Juggler and it failed; that failure is now a governing architectural constraint (Part III).

**ringmaster (an isomorphic synthesis of Stagehand into native Rust/BrowserOxide) Like circus-tent, it shall inherit Stagehand's cognitive vocabulary and core primitives observe (Native tree reduction and action candidate identification), act (Hierarchical selector execution, self-healing via LLM, and coordinate fallback), extract (Schema-guided extraction without arbitrary DOM dumps). Like circus-tent, it deviates from Stagehand in two major ways: Instead of operating as an open-ended natural language agent, it takes an explicit, commissioned TaskEnvelope, executes bounded steps under finite budgets, and exposes the 9 standard connector verbs (Describe, Prepare, Start, Observe, etc.). Stagehand has zero awareness of the hostile, idiosyncratic patterns of enterprise job portals; Circus Tent has solved specific ATS problems (Multi-Page Wizard Checkpoints, Dual Upload Engine, Sharding & Session Concurrency, and dHash Localized Container Crops.

**Hellscape (Go direction. Specified in `3-hellscape-blueprint.md`.).** A hostile SPA fixture that presents increasingly difficult form-filling tasks to a browser-use framework and produces a diagnostic document. It is a form-fidelity laboratory, not an applicant-tracking system and not a fake employer. Its purpose is to hammer the framework and produce improvement feedback.

**job-hunter (language TBD, Python and Firebase implementation specified in `6-get-a-job.xml.txt`.).** Consumes the crawler's feed, scores jobs against the capability profile and the eight playbooks in `capability_profile.txt` / `job_search_queries.txt`, commissions applications via circus-tent, tracks attempts. Storage and language are open questions.

**m0-qualification (Python; retired as standalone. Specified in `5-browser-qualification.md`.).** A harness that qualified browser/driver/binary stacks against an evidence discipline: `None` is not success, an acknowledgement is not a semantic success, a harness timeout is not a native timeout, an HTTP 200 is not authentication. m0 dissolves; its discipline becomes enforced conformance suites (Part VII).

The components are each independently shippable. The failure mode to prevent is integration hell arising from contracts that are *derived from* implementations rather than *specified before* them.

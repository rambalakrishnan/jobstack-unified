## 3. Common evidence and wire rules

### 3.1 Scalar and reference types

| Type | Exact representation |
|---|---|
| `Identifier` | Nonempty opaque string |
| `Revision` | Integer from `0` through `9007199254740991` |
| `PositiveInteger` | Integer from `1` through `9007199254740991` |
| `Digest` | `sha256:` followed by 64 lowercase hexadecimal digits |

| `DurationLimit` | Required `kind: exact`, `unit: ms`, finite nonnegative `value` |
| `Scope` | Required `kind` and `id`; use only kernel scope kinds |

A duration limit is configuration, not a measurement. Zero means an immediate configured boundary, never “unspecified.”

Validation rejects duplicate mapping keys, non-finite numbers, unknown versions, undeclared closed-object fields, invalid date-times/URIs, and normalized bare nulls. YAML is decoded into JSON-compatible values before validation.

### 3.2 Missingness

`Missing` contains required `value: null`, required `reason`, and optional nonempty `detail`.

| Reason | Permitted meaning |
|---|---|
| `not_enabled` | Facility deliberately disabled |
| `not_applicable` | Field has no meaning in this scope |
| `not_observed` | Value has not been established |
| `observation_lost` | Expected or previously available observation is unavailable through loss |
| `unsupported_by_subject` | Exact-scope native absence prevents supplying the value |
| `manual_override` | Authenticated journaled operator decision withheld or superseded the value |

Rules:

- Unmapped adapter behavior does not prove `unsupported_by_subject`.
- Missing native state is not an explicit native `unknown` claim.
- Empty arrays mean established empty collections.
- False and zero are never missing-value sentinels.
- `manual_override` cannot rewrite a subject claim or origin fact.
- Raw native bytes may contain nulls inside artifacts; normalization must apply kernel missingness.
- Required missing fields are supplied as envelopes, not omitted.

### 3.3 Clocks and TimePoint

`ClockDescriptor` contains `clock_id`, `boot_id`, `origin`, `source_id`, `basis: monotonic_offset | opaque_report`, and `unit: ms`.

`TimePoint` contains:

| Field | Transformation |
|---|---|
| `clock_id` | Registered source clock |
| `boot_id` | That clock’s lifetime |
| `origin` | `engine_measured`, `browser_measured`, `subject_reported`, or `manual_reference` |
| `monotonic_offset_ms` | Finite nonnegative offset |
| `utc_annotation` | Date-time or `Missing`; annotation only |

Clocks are registered in the manifest or a `clock_registered` event. Unknown native coordinates use an opaque-report clock; native endpoints are not invented.

A process restart creates a new boot. Document replacement creates a new browser-document clock lifetime where browser measurements are used. No cross-clock or cross-boot subtraction is permitted.

### 3.4 Measurement

Every measurement includes all fields:

| Field | Required mapping |
|---|---|
| `measurement_id` | Unique observation identity |
| `name` | Metric and semantic boundary |
| `scope` | Exact measured scope |
| `quantity` | `duration` or `scalar` |
| `unit` | `ms` for duration; explicit scalar unit |
| `origin` | Actual measurement source |
| `clock_id`, `boot_id` | Registered source lifetime |
| `method` | `endpoint_difference`, `source_value`, `evidence_bound`, or `unavailable` |
| `start`, `end` | TimePoint or reasoned missingness |
| `estimate` | Exact, bounded, or unavailable form |
| `resolution` | Nonnegative declared granularity or `Missing` |
| `censoring` | `none`, `left`, `right`, `both`, or `unavailable` |
| `comparability_group` | Meaningful grouping or `Missing`; not proof of comparability |

Estimate forms:

- **Exact:** `kind: exact`, numeric `value`; method is endpoint difference or source value; censoring is none.
- **Bounded:** `kind: bounded`, `lower_bound`, `upper_bound`; each is numeric or Missing, at least one numeric, ordered when both numeric; method is evidence bound.
- **Unavailable:** `kind: unavailable`, `value: Missing`; method and censoring are unavailable.

Duration values and bounds are nonnegative. Endpoint differences require matching origin, clock, and boot, ordered endpoints, and exact arithmetic.

Binding timers remain `subject_reported`. Independent connector measurements may be `engine_measured`; browser instrumentation remains `browser_measured`. An exact local wait duration is not an exact native execution duration when native work continues.

Observed durations and scalar metrics belong in Measurement. Configuration values, proposed model coordinates, and operational cache state are not silently relabeled independent measurements.

### 3.5 Hashing and storage

Structured records use RFC 8785 canonical JSON and SHA-256. Artifact digests cover exact stored bytes. Array order and string contents are preserved.

Redaction creates a new artifact with a journaled derivation. Hash validity does not authenticate a source.

Artifacts are installed durably before referencing events or publications. A record cannot cite its future registration. Known artifact identity survives byte loss; loss is journaled rather than replaced under the old digest.

### 3.6 Journal submission and envelope

Ringmaster submits `EventSubmission`, never a caller-authored `JournalEnvelope`.

| Submission field | Mapping |
|---|---|
| `producer_sequence` | Monotonic producer-lifetime sequence, or permitted Missing for an unsequenced producer |
| `event_kind` | Manifest-registered kind |
| `event_schema_version` | Registered event version |
| `occurred_at` | Actual source TimePoint or Missing |
| `payload` | Required `data`, `measurements`, `evidence_refs`, `artifact_refs` |

The journal authority assigns and verifies:

- `record_type`, `schema_version`
- `run_id`, `journal_id`, `manifest_hash`
- `journal_sequence`, `event_id`
- `event_kind`, `event_schema_version`
- `role`, `assertion_kind`
- `owner_domain`, `producer_id`, `producer_sequence`, `provenance`
- `evidence_scope`
- `recorded_at`, `occurred_at`
- `causal_refs`, `payload`
- `previous_event_hash`, `event_hash`

Sequence one is `manifest_admitted`; subsequent sequences are contiguous. Duplicate producer sequence with identical content deduplicates; conflicting content is an integrity incident.

Producer gaps, overflow, flush, terminal sequence, closure, and loss are explicit. A closed transport is not producer completeness.

## 4. Runtime and native lifetime architecture

### 4.1 Bounded supervision

The connector front end authenticates, validates, deduplicates, persists, and returns bounded responses. It MUST NOT run long BrowserOxide primitives on the only request/control thread.

The supervisor reserves progress for:

- Local deadlines and observation closure.
- Control requests.
- Durable observations and artifact reads.
- Worker fencing.
- Loss reporting.
- Late evidence ingestion.

An accepted queued task consumes its active observation budget. No workflow primitive begins after its active boundary.

### 4.2 OS-thread confinement

Allocate, enter, reset, and destroy each Page on its owning OS thread. Page, isolate-local values, DOM borrows, solver instances, and closures capturing them never cross that boundary.

A mutex does not make a Page migratable. An async task that may migrate cannot carry a native object across suspension.

Cross-thread messages contain owned bytes, immutable descriptions, diagnostic IDs, and only live HTTP-client handles whose sharing/Send semantics are established. Deserializing an ID does not restore a native object.

A native call is synchronous. A supervisor may asynchronously await its owned result without changing the primitive contract.

### 4.3 Local scheduling states

These are proposed local states, not shared lifecycle enums.

| State | Entry | Allowed continuation |
|---|---|---|
| `admitted_queued` | Durable handle and logical binding | Assigned, expired-before-entry, fenced |
| `assigned` | Current resource/worker ownership | Entry-pending, expired-before-entry, fenced |
| `entry_pending` | Intent and arguments durable | Entered, expired-before-entry, fenced |
| `entered` | Native entry observed | Returned, failed, unresolved |
| `returned` | Return evidence retained | Next authorized step or finalization |
| `failed` | Definite failure retained | Explicit safe recovery or finalization |
| `unresolved` | Completion/effect not established | Late evidence, reconciliation, authorized containment |
| `expired_before_entry` | Boundary reached before entry | No workflow delivery |
| `fenced` | Ownership or command authority revoked | No workflow delivery |

A blocked noninterruptible call does not block local finalization. The owner may remain unresolved. It is not silently replaced by another execution.

### 6.5 Evidence order

For potentially side-effecting calls:

1. Resolve admission, authority, mapping, and artifacts.
2. Durably record exact authorized intent.
3. Recheck owner, context, observation state, deadline, and budget.
4. Enter the native call.
5. Retain native return/error and available effects.
6. Register supporting evidence.
7. Construct, install, and register the primitive record.
8. Derive higher-level observations and claims.

A crash after entry is uncertainty, not permission to repeat the action to repair evidence.

## 7. HTTP, session, reuse, and state-policy seams

### 7.1 HttpClient is not Page

HTTP acquisition is a first-class BrowserOxide facility. An incomplete Page render may coexist with a complete response from the correctly retained client.

Stateful and rotating sessions permit at most one jar-affecting request until redirects and cookie updates complete. Preserve client ID, pool ID, profile, session domain/epoch, request order, and cookie generation.

With process-global session storage, independent domains require separate engine processes unless namespacing is independently verified. Unknown storage is not isolated.

Cookie snapshots are recovery evidence, not permission to distribute rotating sessions or resume them after owner loss.

### 7.2 State domains

| Domain | Contents | Invalid inference |
|---|---|---|
| Browser state | Cookies, storage, Page/document lifetime | New task means fresh state |
| HTTP state | Live client, pool, jar, sequencing | Snapshot equals live session |
| Learning state | Selector/coordinate cache and recovery history | Fresh Page means clean learning |
| Progress state | Established steps and unresolved actions | UI appearance proves safe resume |
| Application state | Origin facts | Checkpoint or click proves commitment |

### 7.3 ContextPolicy transformation

Each StatePolicy contains `mode`, `requirement: required | best_effort`, `resource_ref: MaybeString`, and `baseline: ArtifactReference | Missing`.

Browser modes: `fresh`, `reuse`, `subject_default`, `not_applicable`. Learning additionally allows `frozen`.

- Fresh browser state requires actual mapped fresh-state semantics; reset alone is insufficient.
- Reuse requires authorized compatible state.
- Subject default is disclosed, not called fresh.
- Fresh learning uses an evidenced empty/new namespace.
- Reused learning pins a revision.
- Frozen learning reads a pinned snapshot and suppresses operational write-back.
- Required unsupported policies reject Prepare.
- Realization is observed after Start, not claimed during Prepare.

### 7.4 Checkpoints

A checkpoint retains preparation/request identity, logical handle/key, context/session identity, completed-step evidence, unresolved actions, learning snapshot, budget ledger, and native resume contract when established.

It does not guarantee exactly-once employer effects. Resume cannot repeat completed side effects, ignore unresolved actions, change context, reopen closed observation, or follow merely from lease expiry.

7. Emit explicit inaccessible/unobserved boundary records.
8. Preserve useful accessibility attributes and text.
9. Apply selected profile’s retention rules.
10. Normalize whitespace and serialize within the declared limit.

These heuristics are not universal readiness or application-success predicates. Navigation invalidates prior-document observations and does not reset the task budget.

## 10. Tiered execution, models, and learning

### 10.1 Tier 1

Tier 1 uses a pinned learning snapshot and zero model calls.

Resolution proceeds through current frame path, root path, declared strategy, bounded matches, uniqueness/eligibility checks, and generation validation immediately before mutation.

| Strategy | Mapping |
|---|---|
| CSS | Actual supported native CSS |
| Text | Pinned Ringmaster semantic text matching over native observations |
| Role | Pinned matching over observed role/accessibility semantics |
| Test ID | Pinned attribute convention |
| XPath | Only an established native/V8 mapping; otherwise unsupported |

Playwright syntax is not native CSS. One match from a truncated collection does not prove uniqueness.

Cache hits are recorded only after the configured operation/readback criterion. An action query alone is not a verified hit.

### 10.2 Failure routing

| Condition | Route |
|---|---|
| No match, ambiguity, or pre-entry stale target | Recovery if authorized and budgeted |
| Unsupported grammar | Explicit mapping limitation |
| Definite no-entry action failure | Safe recovery may proceed |
| Possible side effect | Reconcile before action retry |
| Wrong thread, authorization failure, ownership loss | Stop/fence; not selector healing |
| Storage unavailable before intent | No mutation |
| Budget or active deadline exhausted | No escalation |

The source’s Playwright exceptions are not imported Rust error classes.

### 10.3 Tier 2

Inputs are bounded HEAL reduction, fallback text, failed selector/recipe, scoped section labels, and relevant limitations.

The closed model proposal contains:

- `selector`: nonempty string.
- `strategy`: css, xpath, text, role, or testid.
- `confidence`: finite number from zero through one.
- `reason`: nonempty string.

Raw output is retained before repair. A pinned repair implementation may repair syntax, not invent semantic fields. Retain repaired bytes separately, reject duplicate keys/non-finite values, then validate the complete schema.

The baseline permits one additional candidate attempt after an invalid/unusable first candidate. Every provider call counts against budgets; repair and provider failover cannot create an unbounded retry loop.

Before action, re-resolve against the current root, reject ambiguity/staleness, verify commissioned intent, and recheck effect safety.

Verified cache replacement occurs only after the configured operation/readback criterion succeeds. A tentative model candidate is not a verified selector.

### 10.4 Tier 3

Tier 3 requires actual localized capture, geometry, current-layout validation, target grounding, and action support.

The current catalog has no coordinate-click primitive. Ringmaster must not invent `bo.click_at`.

An existing-catalog path may use:

1. `bo.capture` for a localized crop.
2. A model bounding box.
3. Measured coordinate transforms.
4. A pinned read-only V8/native hit-test observation.
5. Serializable hit-test description followed by direct native target resolution and validation.
6. The already declared synthetic DOM action recipe.

This is vision-assisted DOM grounding, not trusted coordinate input. Missing hit-test or action mapping stops the path.

The baseline crop is failing container plus 100 CSS pixels padding, clipped under policy. It never silently becomes full viewport. Missing suitable container or invalid geometry is explicit.

The closed bounding-box proposal contains finite nonnegative `x`, `y` and finite positive `width`, `height`. Its image-space center is `x + width/2`, `y + height/2`. Validate image bounds and transform using actual crop origin, scale, frame offsets, and viewport evidence. Missing geometry is not zero or scale one.

### 10.5 Learning state

Operational selector entries retain step, target recipe, subject/resolver scope, confidence state, hit/heal counts, verification evidence, staleness, and learning revision. Coordinate entries retain step, hash algorithm/version, image digest, perceptual hash, box, coordinate space, geometry evidence, target applicability, creation evidence, hit count, and revision.

Their exact storage encoding is a pinned learning-state artifact contract, not the Circus Tent filesystem schema. Imported source caches retain original bytes and import provenance; counts and confidence do not become current-version findings.

A learning policy must fully define confidence adjustment, missing-prior handling, count increments, stale clearing, and review thresholds before use. Source thresholds `confidence < 0.5` and `heal_count > 10` may be selected as operational review settings, not capability judgments.

A dHash match is image similarity only. Reuse requires compatible step/root, crop, viewport, scale, frame offset, layout, target identity, and permission. Invalid matches do not authorize action.

Background revalidation is separately authorized read-only work against an applicable context. It may not visit targets during Prepare, mutate applications, interfere with active session ordering, or silently alter frozen learning state.

### 10.6 Model conduit

Ringmaster uses an independent Rust-compatible conduit, not a mandatory Python LiteLLM runtime.

The pinned provider policy defines role, ordered providers, model identity, protocol, endpoint reference, credential reference, headers, timeout, token accounting, failover, retention, and privacy.

The source’s Muse and DeepSeek choices are optional configuration, not Ringmaster deployment facts. If OpenCode Go is selected, implement its actual required session header under the pinned provider contract. Use truthful Ringmaster user-agent identity.

Before every call: verify authority/open observation, active allowance, recovery allowance, token reservation, session/shard limits, breaker state, input size, and disclosure permission.

Unknown usage is not zero. Reservations and actual usage reconcile under the pinned policy. Observed counters/durations are Measurements; metrics exposition is not independent evidence.

### 10.7 Circuit breaker and budget dimensions

A source-derived breaker may disable Tier 2/3 when heal rate exceeds 30% in a rolling hour. Its policy must define shard, numerator, denominator, retries, partial observations, window clock, restart handling, sample requirements, trip evidence, and reset authority.

Missing denominator cannot produce zero rate.

Every preparation maps exactly:

- `active_observation`
- `action_count`
- `observation_bytes`
- `recovery_count`
- `model_tokens`

Active observation is connector-enforced. Other dimensions disclose actual enforcer and counting granularity. Required unenforceable bounds reject preparation.

### 15.3 Native cancellation

The `bo.*` catalog has no task-cancel primitive. A separately evidenced Ringmaster task-cancel contract may stop future scheduling, but cannot claim in-flight BrowserOxide interruption without evidence.

Page destruction, process kill, and transport closure are not implicit substitutes. Missing cancel mapping does not prevent bounded local finalization.

### 15.4 Close

`end_observation=false` closes only the mapped native observation transport. True additionally stops new workflow commands and starts bounded drain/finalization. Neither requests cancellation.

The durable Observe API remains readable. No separable native transport is disclosed as a limitation rather than invented. A closed window cannot reopen.

### 15.5 Release

Owner-thread `bo.page_destroy` may implement release only when the external context precisely identifies that Page and the mapping is evidenced.

Release does not authorize shared logout, profile purge, global reset, or unrelated work termination. Missing context identity permits only an evidenced handle-scoped mapping.

### 15.6 Containment

Containment uses a pinned installed policy, scoped authorization, known affected attempts, and unresolved-impact limitations. It does not establish cooperative cancellation or rollback.

Only fixture-origin authority can seal fixture mutation. Ringmaster cannot seal employer mutation authority. Release failure cannot silently trigger containment.

## 18. Lease, recovery, and crash semantics

When Ringmaster uses leased resources, it consumes the exact kernel LeaseRecord, not a worker-authored claim token.

| Lease fields | Mapping |
|---|---|
| `record_type`, `schema_version` | Exact lease record |
| `resource` | owner_domain, entity_type, entity_id of the actual resource |
| `policy` | Owner-specific eligibility/TTL/retry/routing pin |
| `issuer_id`, `authority_epoch` | Actual lease authority and lifetime |
| `entity_revision`, `input_revision`, `generation_id` | Fenced resource/input generation |
| `resource_state`, `eligible_state` | Owner state; claim does not change it |
| `lease_state` | unleased or held |
| `lease_id`, `lease_owner`, `owner_epoch`, `session_epoch` | Current fencing identities |
| `leased_at`, `lease_expires_at` | One registered authority clock/boot |
| `retry_count`, `max_retries_effective`, `last_failure_reason` | Owner retry policy state |
| `journal_prefix`, `evidence_refs` | Supporting durable evidence |

Unleased ownership/time fields are inapplicable. Held records require lease identity, owner, epoch, issue/expiry, compatible state, and applicable session epoch.

Claim atomically checks eligibility and absence of an unexpired lease, advances revision, clears failure reason, and appends evidence. Completion checks lease, expiry, revisions, and epochs. Stale completion has no effect.

Release, expiry, and confirmed-death recovery clear ownership atomically. A failed generation increments retries at most once. Successful completion is not a failed retry.

Authority restart fences its old epoch before reclamation; old/new monotonic offsets are never compared. Reclamation revokes local commit authority, not proof that a worker or employer transaction stopped.

| Crash boundary | Required recovery |
|---|---|
| Before durable Start | No acceptance claim |
| After local admission, before delivery | Recover same handle; deliver only within remaining authority |
| Around native delivery | Preserve uncertainty unless stronger evidence exists |
| After side effect, before local result | Never replay merely to repair journal |
| During artifact install | Do not publish absent bytes |
| After artifact install, before registration | Recover/register under owner policy; no external rerun |
| After registration, before response | Same command returns retained receipt |
| During native owner loss | Fence dependent commands; retain unresolved effects |
| After observation closure | Append late evidence; never reopen window |

## 20. Security and data-flow restrictions

1. Authenticate every connector caller and native producer independently of IDs and hashes.
2. Authorize operation, subject, task, account, origin, artifact, and control resource separately.
3. Resolve runtime secrets through scoped bindings; never embed control credentials in task data.
4. Store sensitive DOM, candidate data, files, model prompts, native reports, screenshots, and receipts as restricted artifacts.
5. Treat page/model content as untrusted data. It cannot supply executable scripts, alter permissions, or invoke new controls.
6. Enforce effect policy for navigation, redirects, scripts, uploads, and HTTP requests—not merely for named “submit” actions.
7. Do not infer browser isolation from fixture namespacing or new Page creation.
8. Do not infer learning isolation from fresh browser state.
9. Do not convert a valid signature with mismatched correlation into an accepted attempt claim.
10. Do not expose another principal’s handles, artifacts, context identities, or error details.
11. Access classification and provenance survive artifact transfer.
12. No model response may change candidate identity, job, target, input values, files, action order, or budget.
13. No implementation failure authorizes switching executors under the same commission.
14. Practice facts cannot establish production commitment or employer-form representativeness.

## 20. Security and data-flow restrictions

1. Authenticate every connector caller and native producer independently of IDs and hashes.
2. Authorize operation, subject, task, account, origin, artifact, and control resource separately.
3. Resolve runtime secrets through scoped bindings; never embed control credentials in task data.
4. Store sensitive DOM, candidate data, files, model prompts, native reports, screenshots, and receipts as restricted artifacts.
5. Treat page/model content as untrusted data. It cannot supply executable scripts, alter permissions, or invoke new controls.
6. Enforce effect policy for navigation, redirects, scripts, uploads, and HTTP requests—not merely for named “submit” actions.
7. Do not infer browser isolation from fixture namespacing or new Page creation.
8. Do not infer learning isolation from fresh browser state.
9. Do not convert a valid signature with mismatched correlation into an accepted attempt claim.
10. Do not expose another principal’s handles, artifacts, context identities, or error details.
11. Access classification and provenance survive artifact transfer.
12. No model response may change candidate identity, job, target, input values, files, action order, or budget.
13. No implementation failure authorizes switching executors under the same commission.
14. Practice facts cannot establish production commitment or employer-form representativeness.
